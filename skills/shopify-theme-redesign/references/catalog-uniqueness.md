# 跨站商品与图片唯一性

批量站默认每个实际款族只分配给一个站，替代旧版“不同组合可共享商品”。同款的颜色、尺码、套数及来源商家的别名不算新款；只改标题、handle、SKU、价格、排序或裁切不能产生独立商品。不同来源 ID 也可能是同款。用户本次明确要求同一官方目录等另有范围时记录该例外，不自行扩大历史翻新范围。

## 先核实容量，再分配

1. 按站数 × 每站独立款数计算总需求。150 款 × 80 站需 12,000 个独立款族，不能用变体行数、图片行数或不同商品组合数充数。
2. 保存具体来源、真实 source product ID、SKU／供应商 style ID、当前可售变体、价格币种与照片。跨来源按可核实型号、同款实物、主辅图及规格归并款族；来源 ID 或文字不同不构成独立款证明。来源泛用 SKU 不能单独证明同款，纯标题相似也只能形成待核对候选。
3. 来源候选数不等于合格款数。完成无品牌筛查、图片检查和款族归并后，再做一次性互斥分配；同款各色／尺码及共享实际照片的商品成组留在一站。不能先各站随机抽样，再用不同 handle 掩盖交叉。
4. 合格数量不足时继续扩充真实来源，报告已核实数量和缺口；限流／失败不当成空页，不绕过访问限制。不可暗中降低每站数量、复用商品或捏造新款。扩源也必须保护商品事实、实际 SKU、图片使用依据与可售状态。

来源已公开且有效的独立 SKU 保留。来源不公开 SKU，或复用同一通用属性串作为许多不同商品的 SKU 时，若真实商品及完整可售规格组合、价格、图片已有证据，可按真实 product／variant ID 给实际规格建立稳定的本站内部库存编码，保留原值和映射并记录“商家内部 SKU，非来源 SKU”；不能为不同来源别名重编 SKU 后声称不同款，也不能凭空创建规格矩阵。数量按 [库存完整性](catalog-completeness.md) 的已授权默认虚拟配额或当前明确覆盖规则处理；内部编码和配额都不证明实际仓库有货。

## 图片范围与真实性

查重同时覆盖 CSV 全部商品／变体／图库图，以及主题轮播每帧、Hero、场景、分类和专题图，包括默认、备用、手机派生图及 presets。跨站同一原图换域名、尺寸、格式、裁切仍算重复。使用营销图和产品图的共同清单，检查跨角色复用；只查 ZIP 内文件会漏掉 CSV 的远程照片。

同站真实商品的卡片与详情、桌面与手机可复用照片；图标、原生支付标识和必要功能标识不计入照片查重。同款重复应重新分配或换商品，不能给商品配另一款照片。不同实物共用通用来源照片时，核对后成组分站，或在仍忠实展示商品的前提下省略非必要通用图片；不能删除实际变体唯一图片来制造通过。

来源 ID／规范化 URL、文件哈希及解码像素用于精确检查；近似图只作看图线索。哈希不同不能证明不是同款，文件唯一也不等于已取得图片许可。保留全部原图／必要清晰预览的核对记录，不把自动无命中宣称为法律清查或全球无重复。

## 工作清单与审计

在工作目录保存，不进入最终成品文件夹或可分享技能：

```json
{
  "sites": [{
    "site_id": "batch/category/site-01",
    "expected_products": 150,
    "csv_paths": ["site-01/csv1.csv", "site-01/csv2.csv"],
    "products": [{
      "handle": "actual-stable-handle",
      "product_key": "source.example:12345",
      "family_key": "reviewed-style-family-12345",
      "source_product_id": "12345",
      "source_url": "https://source.example/products/actual-item",
      "identity_review": "已核对来源型号、实物主辅图及规格；颜色尺码归为同款",
      "alias_keys": [],
      "images": [{
        "source_url": "https://cdn.example/images/actual-item.jpg",
        "parent_source_id": "source.example:actual-photo-id",
        "path": "media/actual-item.jpg"
      }]
    }],
    "images": [{
      "role": "hero",
      "source_url": "https://images.example/photos/actual-photo.jpg",
      "parent_source_id": "provider:actual-photo-id",
      "path": "site-01/theme/assets/hero.webp"
    }]
  }]
}
```

示例省略其余实际商品和分片，正式清单必须完整。路径相对清单位置解析。`identity_review` 是人工／来源归族记录，不是脚本替人判断；不能全部填“ID 不同所以独立”。`alias_keys` 记录已核实同款的其他来源键，帮助跨站合并。`source_product_id` 与域名、具体商品 URL 均参与检查，不仅比较自行填写的 `family_key`。营销图与产品图可复用同一素材证据结构。保留下载到工作目录的真实图片，以便校验内容；缺文件只可做来源级初审，不能算完成图像查重。

```text
python scripts/audit_catalog_uniqueness.py --plan WORK/catalog-plan.json --report WORK/catalog-unique-audit.json
```

可重复提供 `--history` 检查已登记历史；历史未完整登记时明确未检查范围。单站修订保留原 `site_id`，当前清单以 `revision_of` 等于该 ID 明确声明；不能用同站 ID 把不同商家混为修订。脚本只读显式输入，不联网、不改成品。`0` 表示清单内自动检查无阻断和待核对，`1` 为结构／精确重复／CSV 对不上，`2` 为图片文件、身份审查或近似看图证据缺项。它不检查“高级感”、商品所有权或许可，也不能发现所有换角度／任意裁切。

交付前重新读取最终 CSV 的全部 handle 和图片 URL，对照清单及完整数量；不能审计候选后交付另一套目录。将营销图设计审计与本目录审计一同保留。换品后同步分类、首页、指南、PDP 与实际预览目录；原生购物、分类、价格、授权库存和可编辑性照常验收。改已有本地成品时先备份，验收后再替换；CSV 导入不会自动删除店内旧款，不擅自删除后台商品。
