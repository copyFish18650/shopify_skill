# 整站层次、陈列与页面完成度

用于整站设计和参考适配。基础站按 [基础标准](basic-store-standard.md)，精品站按 [精品标准](premium-store-standard.md) 核对适用页面与组件。精品优先保留用户认可的历史精品整站，未指明时以 Cozyster 为基准；约 85% 成熟视觉／结构、15% 局部品类适配是设计取向而非像素评分，导航、卡片、PDP 和模块节奏均可复用，不要求各页为差异重构。自主设计按 [站间差异规范](site-diversity.md) 将本站视觉延伸到集合、详情、搜索、购物车和服务页；基础规则不变。各模式的图片／商品去重和完整购物路径不变，不强制加入另一参考的组件；记录观察范围。

## 从首页延伸到整站

先选择适合这批商品的主次：影像专题、商品轨道、按用途目录、编辑图与真实商品混排、实用指南等。尽早出现真实商品，避免大标题和留白占几屏。主网格维持桌面 4 / 手机 2；可增加不同密度的专题陈列，读取真实集合，缺商品时不制造款式、价格或销量。

精品保留成熟基线的模块顺序、比例和信息密度，局部按品类替换图文或调整必要入口，不为站间变化重新编排。自主设计可组合图像菜单、短照片带和专题陈列，按本站购物任务形成不同构成；基础规则不变。原生功能底稿仍不能直接当作已打磨的精品视觉基线。

## 把购物路径连接起来

借鉴 [Cozyster 整站对照](cozyster-layout-study.md) 时，先区分已有功能、本店选用的新实现与参考站未验证的空壳。首页专题通向真实集合／商品，空购物车可接实际商品陈列，详情中的规格和服务信息应帮助完成选择。精品可沿用成熟专题顺序和排版，仅在真实品类／目录需要时调整；自主设计再按本站构成选择专题数量与排版。场景图片与商品继续按跨站去重要求替换。

- 吸底购买／手机底部导航按需求选用。吸底栏读取当前变体、实际双价、库存和数量；底栏使用真实路由／购物车状态。处理安全区、键盘和其他浮层，避免互相覆盖；停用增强后仍有原生购买表单。
- 完整快速查看应使用当前商品真实表单、媒体和选项，不把“选择选项”跳转或图片放大冒充快速查看。慢载／失败返回商品页，多实例不产生重复 ID、失步价格或错误规格，购物车响应与错误真实可见。
- 推荐来自实际推荐结果或有效集合。空结果隐藏，不补示例卡；最近浏览仅来自真实访问，销量排行须有依据，普通集合不冒充个性化或畅销算法。
- 联系页可组合原生表单、获准公开的资料和已确认服务时间；About／指南补真实选品与测量说明。没有实际地图、文章、评论或订阅配置时不留模板空壳。Reviews 保持默认关闭；Newsletter 一般关闭，但精品严格复刻按本次参考截图／明确指示实施真实表单与开关，不被旧默认关闭覆盖。

基础适配器未自动提供上述全部能力。记录本店采用项、数据来源、回退和验证范围，在对应建站任务实际实现并实测，不只修改说明就称功能已落地。

## 页面职责

| 页面 | 要完成的设计与状态 |
| --- | --- |
| Header | 保留原菜单，同时显示真实分类；按目录大小选择图像菜单、分组目录或简洁下拉。鼠标意图、键盘、手机展开和关闭均可用。不能为凑复杂而虚构系列或 About 历史。 |
| 集合/分类 | 清楚的标题与上下文入口，紧凑的筛选/排序层级、活动条件、重置和原生分页。精品优先沿用成熟工具条／侧栏与手机抽屉；其他模式按本次设计选择。手机继续使用同一组原生输入。 |
| 商品 | 真实媒体/视频、价格、规格、不可售状态、数量规则和原生购买。照片可成对、焦点图库或叠放；短规格列表可渐进增强为按钮，长列表保留选择器。加入可访问媒体查看和适当详情披露，不编造规格/材质/功能。 |
| 搜索 | 初始发现、查询、结果、无结果及翻页均成立；商品/文章/页面结果分别正确显示。查询与搜索范围不能被排序重置。 |
| 购物车 | 清楚的商品/规格/单价/数量/行价/总计层次，真实折扣和错误状态；空车提供实际购物入口。保留备注、原生更新、删除及结账表单。 |
| 内容与服务 | 联系表单、About、指南、博客/文章、Footer 政策阅读界面使用同一字体、容器和表单语言。仅使用已有内容或本次可编辑正文，不编品牌事实。兼顾 404 和旧式账户模板；Shopify 托管结账及新版账户不由主题控制。 |

## 商品数量与原生筛选的非显然边界

- `collection.products_count` 是过滤后的商品数量；不是 ID。显示为 “1 product / 1,536 products”，搜索用 “results”；提供隐藏开关时只隐藏展示，不删除数据或查询行为。真正的 SKU/variant/product ID 不无故暴露给顾客。
- 筛选读取 `results.filters`、`filter.values`、`param_name`、`value`、`active_values` 和原生 `url_to_remove`。数量为 0 且未选中的值禁用；已选中的 0 值仍可移除。大于 50 项分批渲染，确保设置和循环不截断。
- 使用 GET 原生表单。排序、重置、价格范围和条件移除保留当前标签路径、Type/vendor 的 `q`、搜索词、搜索 `type` 和本地化路由；清除 filters 不应清掉顾客购物上下文。输入金额按 Shopify 数据约定转换，检查最小值不大于最大值。
- 自定义控件保留语义、焦点、原生表单能力与无 JS 回退。手机抽屉移动同一份输入，不复制重复 ID/互相冲突的表单；验证 Escape、关闭后焦点、拖动窗口及未提交选项。应用中不伪造成功结果或库存。
- 没有配置的 Shopify 筛选不应编造出来。集合/Type 导航从当前店数据读取；旧来源标签映射可作为明确可选项，不能把上次品类文字写死在新店顶部。

## 可复用实现与验收

`scripts/apply_storefront_depth.py` 仅适配本技能自己的原生底稿，提供原生筛选、图像目录、图库/规格按钮、服务链接和页面基础样式。`prepare_theme.py` 自动应用；已有自有基线可单独执行。商家任意原主题先识别插入点并保留其功能，不直接替换 Header/模板。脚本是一次性构建适配器，修改既有成品应在副本完成、检查差异后打包。

`assets/retail-native/editorial-assortment.liquid` 是可选陈列 section，默认不注入首页；通常使用 image picker。构建器明确传入 `bundled_editorial=True` 时才保留 included photo 分支，同时必须提供匹配的三个 WebP 资源和正确尺寸。它不是未来每站必须出现的固定模块。公开商品全部仍来自 Shopify 对象。

验收要使用真实商品与有内容的 filters；另覆盖空店、长标签、价格/可售条件、已选条件、0 结果、仅 Type、混合目录、超过 50 项、手机 320px、无 JS、减少动态效果、Theme Editor 重载及 Cart API。看各页面桌面与手机实图，执行所选交互。没有实店导入时明确报告本地预览范围，不把本地 200 或官方静态检查当实店证明。

品类文案也要逐页核对：搜索初始标题、联系页保存配置、集合总览标题、商品 accordion 与 schema defaults/presets 都可能保留种子文案。按当前品类改正文和值，保护 ID/类型/引用；不要仅搜索首页文字或对整个源文件全局替换品类词。适配器仅清理确知的旧底稿原句，不应重置商家自定义内容。
