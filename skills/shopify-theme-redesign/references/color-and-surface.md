# 配色、色面与明暗结构

基础站、精品站和自主设计均执行 [站间差异规范](site-diversity.md)，其中精品优先保留用户认可的历史精品色面与视觉层次，未指明时沿用 Cozyster 基准。约 85% 成熟视觉／结构、15% 局部适配是设计取向，不是像素评分；精品可复用同一套主地、陈列面、阅读面和明暗节奏，不为站间区别强行换成深色或重组色面。以下独立色面与主要构成差异要求适用于自主设计；基础规则不变。所有模式继续核对真实图片、文字对比度和原生颜色设置。

用于自主设计、多站批量设计及用户要求配色更自由的任务。颜色是页面构成的一部分，白色、浅灰和低饱和浅底没有默认优先权。可以由深色主地、饱和纯色、明暗交替或浅色与强色块并置组织整站；这些是可选思路，不是固定模板库，也不要求全部站变黑。

## 先决定颜色承担什么

结合商品照片、选购任务与参考，确定主地、陈列面、阅读面、操作和强调区之间的关系。深色可承载大面积目录，强色可承载专题或主要购物区，浅色可用于照片和长文阅读；各自面积与顺序由本店构成决定，不规定统一百分比。早期白/浅灰与绿/蓝/珊瑚红偏好、以及紫/米黄/棕限制不作为永久配色清单；当次明确品牌限制仍优先。避免复杂渐变和无用途的多色装饰。

基础与自主设计的多站任务仍在编写前比较近期实际截图，写清各站的色面结构与主要版式差别；遮住店名、商品图和小面积强调色后仍是同一种白浅底商城时，调整主要构成或主地／陈列面关系。精品多站允许共用成熟色面，以配图、品类文案和必要局部调节完成适配，不以明暗大变化作为验收条件。不要机械轮换“十套配色”，也不要让顾客访问时随机变色。

## 配色质感与文字清晰度

先从商品和场景照片中确定一个协调的主色方向，以中性色承担主要陈列和阅读，少量强调色用于关键操作。主地、卡片、阅读面和重点区有清楚的明暗层级，避免相近灰度糊成一片，也避免高饱和色互相争抢注意。精品优先保留成熟基准的配色关系，再微调色相和局部强调；变化幅度不能盖过照片、价格和购物入口。不独立随机抽取背景色与文字色，不以整页随机 RGB 或固定轮换色板代替审美判断。

- 每种表面成对确定背景／前景，以及按钮底／按钮字、辅助字、链接、边界和焦点色。深底用足够明亮的前景，浅底用足够深的前景；强调色不自动等于适合小号正文的文字色。区分主次优先调整字号、字重、间距与位置，不靠把文字淡到难读。
- 普通正文、导航、商品名、现价、划线价、辅助文案、表单占位和按钮文字与实际背景的对比度至少 **4.5:1**；大号文字按 WCAG 定义至少 **3:1**，不能因为“标题”或“粗体”就自动降低门槛。极细字体即使数值刚过线也须看实际渲染，必要时加深或加粗。
- 用于辨认控件、必要图标、选中状态和焦点的视觉部分，与相邻底色至少 **3:1**。装饰分隔线不必一概加深；真正禁用控件可有适当弱化，但状态和原因仍应可辨，商品资料、价格与政策不能借 disabled／muted 变得看不见。
- 用浏览器最终计算颜色，合成文字／祖先透明度、半透明面板、遮罩及后方底色后再测，不只比 theme settings 中两个色号。检查 CSS 变量格式、继承和覆盖：不能留下浅底白字、深底黑字、按钮底与按钮字同色，或下拉／浮层继续继承另一个色面的前景。
- 图片叠字按文字所在局部、每一轮播帧及桌面／手机裁切检查，不能只取整图平均色。必要时加克制的遮罩、稳定文字底板或将文字移到图外；图片加载失败时仍有可读底色。不要让大面积遮罩抹掉商品细节。
- hover、focus-visible、active、选中、加载和错误状态都要保留清楚文字，菜单、筛选、快捷查看、购物车、订阅与本地化选择器展开后同样检查。可点击链接不能只靠难分辨色差表达，焦点与当前项应易识别。
- 不对整个卡片、价格区、Footer 或政策正文降低 opacity 来营造高级感；滚动显现／淡入不能使关键内容在无 JS、加载失败、店主动效关闭或 prefers-reduced-motion 时停留在透明状态。静态验收等待正常过渡结束，另验操作过程与回退。

数值依据：[W3C 文字最低对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。这些是适用颜色对的最低要求，不是对整站自动宣称无障碍合规；字体、裁切、层级及真实操作仍须看成品。

## 让编辑器和组件使用同一系统

保留现有主题设置兼容性；自主构建时为所用原生 `color_schemes` 提供匹配的 schema、role、数据实例、默认值及保存引用。将背景、文字、按钮及按钮文字等原生设置映射到实际 CSS；需要时再定义表面、弱化文字、边界、焦点和错误等语义 token，不强制另一套设置 ID。默认值、presets、保存 JSON 与重新添加的 section 都采用本店方向。

主题颜色要延伸到首页、集合、商品、搜索、购物车、内容／服务页，以及菜单、筛选抽屉、媒体弹窗、页脚本地化控件和表单；政策正文使用独立页面。排查继承组件中的写死白底、深色文字或浅色边框，避免暗色页面出现突兀白块或不可读文本。根据组件所在色面取 token，验证选中、hover、焦点、禁用、加载、错误和成功状态；切换编辑器颜色方案后实际页面应有相应变化。浅色照片面或阅读面可以保留，但必须是明确的表面角色。

商品原图的颜色和背景属于商品资料。不可为配色统一而 `invert`、滤色或自动去白，造成商品颜色、材质或细节失真；可通过真实图片周围的容器、留白和陈列方式建立色面。场景图默认从互联网选真实照片，按本次光线、环境和构图筛选，不自行生成；不把场景鞋服宣称为目录中的某个真实 SKU。

## 实际看成品

至少查看约 1440px 桌面、768px 平板与375–390px 手机，按本店长名称或组件风险补边界宽度。对每个实际使用的色面和关键操作状态记录代表性的文字／背景与控件对比度，打开菜单、筛选、政策和联系表单后再检查，不能只验闭合页面。分别看主地、卡片现价／划线价、辅助字、输入框、选中项、错误提示、焦点、公告和 Footer；图片叠字逐帧逐裁切核对。发现看不清的文字就修颜色对、继承或透明度后复验，不以 Theme Check、静态色板或配置中的“白字”证明可读。

同时看整页色面节奏和相邻站的实际区别，保留简短观察与修正。静态色号、自动截图相似度或风格评分不证明精致；原生购物、4/2 商品网格、真实商品、可编辑政策、手机速度和减少动态效果持续优先。
