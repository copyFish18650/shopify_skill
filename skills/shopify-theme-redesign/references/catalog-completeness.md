# 商品类别、分类关联与库存完整性

适用于本流程所有带商品 CSV 的创建、抓取和重做任务。用户要求导入后后台也有完整商品资料；只做到前台有商品、Type 有值和公开状态可售，不算目录交付完成。这是本流程质量标准，不表示 Shopify 导入器把所有这些列都设为必填。

## 三套分类分别填写

| 后台／CSV 字段 | 本流程要求 |
| --- | --- |
| 类别：`Product category` | 每件商品填写当前 Shopify Standard Product Taxonomy 中有依据的最具体类别，使用官方短 ID 或完整英文路径。先查稳定版分类表，不猜 ID、不写任意 `Sneakers` 或店内集合名替代，也不只填 Google Product Category 后就称本列已完成。 |
| 产品类型：`Type` | 按实际商品整理顾客容易理解的自定义类型。可重整来源站错误主分类，保留原分类与判断依据；同商品一个主 Type，不能把标准类别和本字段混为一谈。 |
| 店铺集合：`Collection`／标签映射 | 默认 CSV 写入一个有效主集合名称，使导入时关联／创建集合。其他成员关系可按主技能用标签映射到原生分类视图；这不自动创建多份后台集合或导航菜单。既有自动集合须满足其条件。 |

产品级字段写在同 handle 的首商品行即可；变体续行、额外图片行不必重复。验证时按 handle 汇总，不能把合法空续行误报为漏填，也不能只检查文件有表头。图片、标题或来源导航只用于判断依据，不能把没有核实的属性当事实。

分类表从 [Shopify 官方稳定发布](https://github.com/Shopify/product-taxonomy/releases/latest) 获取，当前推荐资产为 [categories.en.json.gz](https://github.com/Shopify/product-taxonomy/releases/latest/download/categories.en.json.gz)。记录版本、下载时间、来源和哈希；不要把 main 的 unstable 或已弃用 dist 路径当成稳定生产分类表。执行时核对最新官方格式，当前 JSON 为 `version` 和 `verticals[].categories[]`；对象的 `id` 是 GID，写 CSV 时取末段短 ID，或使用 `full_name`。不在可分享技能里打包不断过期的大型分类快照。

## 按规格填写库存

- 新目录默认启用 Shopify 跟踪：逐个导出变体写 `Inventory tracker=shopify` 与 `Inventory quantity`；旧兼容表头是 `Variant Inventory Tracker`／`Variant Inventory Qty`。不能只给每件商品第一规格填库存，也不能把数量塞进描述、标签或主题代码。
- **新建本地目录的默认数量为店主已授权的虚拟配额：每个真实可售规格独立随机取 60–99（含端点）的整数。** 该默认不需要每批重新确认；当前用户明确给出其他配额、要求实际库存同步，或明确选择不跟踪时，从其要求。修改已有目录只保留该目录已确认的库存规则，不因本技能更新而自动重配；调整实店库存或仓库另需当前任务授权。
- 在工作目录保存规格到数量的分配映射及 `merchant_virtual_allocation` 依据。使用来源域名＋稳定商品／规格 ID 定位；来源无规格 ID 时，用已核实的 SKU 与实际选项组合等稳定身份定位，不能只靠易变的标题、CSV 行号或排序。首次生成后保存每个结果；重跑、重新分片、改价或重打包时读取原值，只有新增真实规格才新增分配，不在顾客访问时随机。分配记录不进入主题 ZIP 或共享技能；CSV 只写平台支持的跟踪与数量字段。
- 保留源 SKU／选项、公开可售状态、源数量（如有）、含时区的采集时间和分配对应关系。分别标记“供应来源库存快照”“店主已核实可履约库存”和“店主授权虚拟配额”，不得互相冒充；60–99 配额不证明来源仓库或店主实仓有货，也不表示持续同步。不要据此生成虚假紧缺／“仅剩几件”促销文案。
- `available=true`、In stock、可下单、继续销售和未跟踪库存，都不能推导出具体数量；默认 60–99 的依据是上述店主授权，不是这些公开状态。来源没有数值不再单独阻塞采用默认虚拟配额的新目录；若当前任务明确要求实际库存同步，则继续补查或引导提供实际数量，不以虚拟配额代替。不能把 `#待填入` 或待确认文字当数值导入。
- 缺少当前适用规则要求的数据时，CSV 标记为未完成。不得为了赶交付静默留空 tracker、默认未跟踪、打开缺货继续销售，或用数量 0 导致全部不可售。只有用户明确选择不跟踪库存，才采用该例外并在报告说明。
- 普通“有库存商品”目录排除不可售规格，默认 `Continue selling when out of stock=deny`（旧列 `Variant Inventory Policy`），不把缺货、预售或负数状态伪装为现货。已配置第三方库存／履约服务的现有店按实际对象保留，不擅改为 Shopify 自有库存。
- `Fulfillment service` 按实际来源／目标设置填写；普通手动履约为 `manual`。库存、继续销售及履约列一起核对，不能遗漏相关依赖字段。

## 单地点与多地点

产品 CSV 的 `Inventory quantity` 只适用于单地点店铺。新店本地准备若按单地点输出，应明确这一适用前提；目标店有多个地点时先核对实际地点和库存分配，按 Shopify 原生库存 CSV、后台批量编辑或获授权 API 处理，不能把总量当成每个地点的库存。

默认 ZIP＋商品 CSV 的交付习惯不改变平台限制。若确实需要多地点库存文件或后台配置，向用户说明具体缺项与可行处理，确认实际范围后办理；不得悄悄加入第三个必装文件、假称同一产品 CSV 已完成多地点分配，或为维持两文件而关闭跟踪。未获后台操作授权时只准备本地资料。

## 其他商品资料与交付检查

标题、真实描述、稳定 handle、实际规格组合、SKU、图片及规格图、双价、币种、发布状态、分类和库存应一起核对。实物标记需要配送；重量、材质、尺码、条码／GTIN、成本、产地等有真实依据才填写，不为填满表格制造认证、条码或尺寸。未知可选字段与上述必验的类别／库存分开报告；有特殊业务依赖时询问确切缺项。

打包前对本次每份 CSV 执行：

```text
python scripts/catalog_audit.py PRODUCTS.csv --taxonomy CURRENT_CATEGORIES.en.json.gz --report WORK/catalog-audit.json
```

该只读检查验证单地点目录的标准类别存在、Type／主 Collection、逐规格跟踪／正整数数量、SKU、基础商品资料和相关导入字段；不代替语义分类、图片全量可访问性、实际库存或授权配额依据、已确认双价及实际后台导入检查。采用默认虚拟配额时，另将最终每个规格与保存的分配映射逐行比对，确认全部为 60–99 整数且重跑未变；正整数检查本身不证明采用了正确配额。`--allow-untracked` 只用于用户明确选择的不跟踪例外，不能用来绕过本次要求；多地点本身不在该脚本的覆盖范围。

按商品及变体统计覆盖率和缺项，不只报“CSV 格式正确”。记录标准类别与类型／集合映射、每个规格的数量依据和跟踪器；交付时简述本批采用虚拟配额或实际库存，不把配额称为已核实实仓。缺值或无效值必须修复或明确阻塞完整目录交付。有实店访问条件时查看／导出实际导入结果，确认后台类别不空、逐规格跟踪及数量正确、分类成员与前台一致。只有本地检查时明确未验证实店，不宣称上传 ZIP 或更新技能已补齐旧后台商品。
