# 建站命令与交付范围

用户要求“从头做完整站点”时，先落实以下已有默认：美国网店、个人经营、当前任务姓名和证件地址、站内联系表单、账户邮箱不作客服邮箱、已确认政策底稿、全站可售目录（明确要求抓取时）、本次基础复刻／精品复刻／自主设计模式、主题 ZIP、独立 CSV 与每站实际首页截图。不得为让命令完整再次索要所有已确认时效和费用；缺姓名等少数资料时继续不依赖它的工作。

## 最简输入

用户说“基础站”即采用 [基础高复刻标准](basic-store-standard.md)，默认参考 EstateKid；说“精品站”即采用 [精品高复刻标准](premium-store-standard.md)，优先沿用用户认可的历史精品，未指明具体成品时用 Cozyster。精品默认约 85% 保留成熟结构／15% 局部适配，无需用户每次重复锁定组件；基础与自主模式仍按各自差异要求。各模式覆盖全部卡片、详情与手机，商品／主图去重继续执行。新指定视觉参考优先；商品来源另列，不因商品来源网址覆盖视觉参考。例如：

```text
$shopify-theme-redesign 本次品类是[品类]，做基础站，高度复刻 EstateKid 整站；商品[从指定来源抓取全站可售商品和分类／稍后自行导入]，最终放入[目录]。本次经营者姓名：[姓名]；证件地址：[地址]，暂缺则 #待填入。
```

```text
$shopify-theme-redesign 本次品类是[品类]，按精品站标准高度复刻[参考网址，未另定则沿用Cozyster]的整站布局、卡片、详情和手机端；商品来源为[来源或稍后自行导入]，ZIP、CSV 和首页截图放入[目录]。本次店铺资料：[仅用于本站的经营者姓名、证件地址；暂缺则待填]。
```

目录、CSV 份数和是否抓取按实际要求；没有商品资料时不制造空 CSV。每站默认再附一张最终主题的实际桌面首页截图，与 ZIP、CSV 同目录，按 [首页截图交付](validation-and-delivery.md#首页截图交付) 验收，不用用户每次补写。各模式默认执行 [主图去重和分模式设计变化](site-diversity.md)，不用用户每次补写“不要重复”。精品以成熟基准高权重保留并核对精细度；基础与自主模式按各自规则变化。经营事实和原生后台边界不变。

新建本地商品目录的库存默认已经获准：为每个真实可售规格独立随机分配 60–99 件虚拟配额，保存后重跑沿用，不再每批询问 99／1,000 件；详细身份映射与验收见 [库存完整性](catalog-completeness.md)。用户可在命令中覆盖数量或要求实际库存同步；旧 CSV／实店库存不自动回改。该默认仅准备本地导入数据，不授权调整仓库、实店库存或发布，也不证明物理库存。多地点店铺的库存导入仍按平台边界单独处理。

```text
$shopify-theme-redesign 本次品类是[品类]，参考并抓取[官网网址]全站可售商品和分类，个人经营者：[本次姓名]；证件地址：[街道、城市、州/省、邮编、国家]。按技能默认政策自主设计，ZIP、CSV 和首页截图放入[品牌(品类)]文件夹。
```

自主模式没有特定视觉时做出与近期作品不同的构成和交互；精品模式没有新视觉时继续沿用成熟基准的小比例适配。不把风格确认当审批关口。需要限定鞋履/常规新品/不含二手等范围时直接写在命令中；“全站”与先前举例冲突时按最新范围。新任务的真实资料优先于前项目，不复用示例个人姓名。

无需每次重写默认要求：每站从 10%、15%、20%、25% OFF 四档随机选择一次并保存、售价为有依据原价乘相应倍率，保留划线价并让顶部优惠文案与本站 CSV 一致；Footer 文档走真实独立页面并去重，含原生语言／国家及对应货币控件。没有目录或价格依据时先完成模板而不虚挂优惠。用户可明确覆盖促销比例；可附“同品类分别给 csv1…csv5”改变默认一份 CSV 交付。Pages／语言／Markets 的实际后台设置仍按下述边界处理，不隐含 ZIP 自动创建或启用。

每个新站必须绑定本次唯一一份店主资料，明确对应的参考/目标店铺与工作、交付目录。同一站迭代可沿用该站已确认资料；切换站点必须重新绑定，不能因为聊天里出现过某人的整套资料就默认以后都用。资料缺失时问当前站缺什么，不用上次姓名填空，不为满足“唯一”编造新身份。多份资料与多个站点的对应关系不清楚时先明确归属。

用户可在命令后附“本次店铺资料（仅用于本站）：经营者姓名：[姓名]；证件地址：[街道、城市、州/省、邮编、国家]”。只需要任务实际所需字段，不要求发送含密码和身份编号的原始资料包。原始包中的账户邮箱、密码、snCode 和身份编号不进入公共成品或共享技能；姓名与证件地址仅用于对应本站，不能写成共享技能默认资料。

目录默认 output/shopify，用户另定从其要求。店铺显示名和域名可由导入后的 shop.name/shop.url 获取，尚未定名不阻断本地设计。只需当前任务姓名与证件地址，不需要账户密码、身份编号、证件原图或付款凭据；可直接提供按证件整理的文字地址。

## 本地成品完成到哪一步

完整原生主题及必需模板、真实商品/分类关联、可编辑首页与 Footer、适用政策／服务正文、实际原生商品和购物车路径、所选交互及响应式检查，按已有验收流程完成，并保存每站实际首页截图。底稿十四份正文不表示 Footer 必须列十四项；精品严格复刻的可见结构和 Newsletter 开关按本次参考截图，其他必要正文可编辑保留／归档。先上传 ZIP，再在产品中导入 CSV；截图仅供预览，目录不依赖第三份安装文件。交付中列明必要的隐私/法律核对项，不把稿件状态称为全部经营事实已核实。

无目标店连接时区分本地模拟、官方静态检查与真实导入，首页截图也标明来自哪种预览。ZIP 不会创建后台 Policies/Pages、配置收款/运费/域名、设置联系表单收件人或自动发布。交付本地文件和截图不等于线上店铺全部配置已完成。

## 若要继续实店落地

用户可在命令后补充：

```text
完成文件后，继续在我有权访问的[目标店铺网址]导入草稿主题和 CSV，核对商品、分类、首页、Footer、购物车及联系表单；先保留为草稿。
```

需要当前可访问的目标店铺、正确主题及本次操作授权，不复用历史店铺或浏览器编号。根据明确授权完成导入和验收；是否发布按本次授权处理，不将“参考某站”当发布授权。保持支付、订单、结账和原有导航功能。

店主仍需完成账户、收款方式、实际配送/税费、域名及后台收件配置，并核对实际隐私配置和必要披露。只协助本次授权的动作；联系表单显示/本地提交检查与真实邮件投递分别记证，未进行真实投递不能称已送达。无需用户在聊天里粘贴密码或支付/身份凭据。
