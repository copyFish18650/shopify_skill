# 独立设计、内容职责与精致度

各模式都执行[主视觉去重与站间差异](site-diversity.md)，但精品站优先沿用用户认可的历史精品布局；未指明时以 Cozyster 为基准。精品默认约 85% 成熟视觉／结构、15% 品类局部适配，这是设计取向而非像素比例或评分。导航、卡片、PDP、模块节奏和排版可以复用，无须逐组件另行锁定，也不因与同基线作品相似而重构。以下构成与结构差异要求对精品按上述复用优先级解释；基础站与自主设计仍按原有标准。各模式的图片、商品去重、完整购物路径和真实内容要求不变，不把两种参考的组件全集机械拼接。

## 从商品和购物任务开始

先判断顾客主要在做什么：发现系列、比较器材规格、挑选款式、按用途选购，还是搭配整套用品。再决定页面如何让人看见商品、理解差异并进入购买。服装不必每次都编辑风，运动器材不必每次都科技风；风格由本次商品、参考与品牌资料共同支持。

阅读 [reference-layout-library.md](reference-layout-library.md) 的实际来源和设计推演。借鉴一至两个合适原则即可，不必把三个站点拼进一页。用户最新参考优先；页面不可达时说明观察范围，使用已核实结构、用户截图及独立设计继续。

在本次输出目录保留简短设计记录，写清“为何适合这批商品”；精品记录成熟基线、保留部分和必要局部适配，其他模式仍记录与近期作品的构成区别。设计记录不是用户审批关口，正常设计选择直接执行。对照历史要看截图，不能只根据作品名或色号声称不同。

## 可以自由决定的设计

精品只在必要的局部适配中选用以下手法，不要求逐项更换成熟布局；基础与自主设计保持原有选择空间。

| 设计问题 | 可作出的选择（不是穷举菜单） |
| --- | --- |
| 首屏承担什么任务 | 系列影像、单个专题、产品索引、并列购物入口、商品与场景的编辑组合；不强制左文右图。 |
| 图片如何组织 | 满幅、窄幅、双幅、不同大小拼接、纵向使用场景或细节；先决定构图，再寻找并选取真实素材。 |
| 文案如何出现 | 图外标题、低位叠字、边缘注释、短标题或单 CTA；不要求所有首屏都有小标签、描述和两行标题。 |
| 色面如何组织 | 深色主地、饱和纯色、明暗交替、浅色与强色块并置；按 [配色与色面构成](color-and-surface.md) 决定整站关系，不默认白底、浅灰区和深色 Footer。 |
| 页面如何推进 | 商品先行、分类先行、场景与商品交错、专题引入后接目录；首个购物区要容易到达。 |
| 分类入口如何呈现 | 大小组合、简洁索引、横向图卡、全宽分区或紧凑网格；仍读取真实集合/Type，并显示空店分类位。 |
| 浏览时如何反馈 | 实际商品辅图切换、快捷操作显现、分类与图像联动、可展开的真实细节；按商品选择，执行 [retail-interactions.md](retail-interactions.md)。 |
| 服务信息放哪里 | 商品区旁、紧凑文字行、FAQ 或 Footer 内；三项通用信息不必变成三个图标盒子。 |
| 第二张图做什么 | 第二专题、搭配叙事、使用场景、分类组合的一部分；不要求独立的左右图文各半 section。 |
| Footer 如何收尾 | 明亮、暗色、细线、紧凑索引、宽阔编辑排版；服务与政策入口及可编辑能力持续存在。 |

这些选择之间要有一致逻辑。不要逐项随机抽取，也不要把它们做成每次循环的几个风格代号。精品保留成熟基线的构成、卡片系统和色面关系，在必要局部适配中维持其精细度；不为变化任意重排。自主设计选一个有主次的构成，允许局部打破对称；避免近期作品都以白色或低饱和浅底占据主体、只在按钮和页脚变色，检查整页的主地、陈列面与明暗推进。

有原主题时保护功能和保存配置；无原主题时允许重写骨架展示组件。基础与自主设计仅增加一份 CSS、改色和换照片不构成默认合格成果；精品采用成熟完整基线时不以改动规模判定合格，重点核对原有质感、品类适配和全页完成度。将本次设计同步到 schema defaults/presets、保存 JSON、图片焦点与响应式设置，防止删除后重加模块又出现旧版视觉或不相关品类。

交互也是本次设计的一部分。精品优先保留成熟基线经验证的交互，只按实际图片、规格与购买方式作必要调整；自主设计不机械移植上一个项目的整套动效。可以有精致的悬停、展开和滚动反馈，默认克制且可关闭；不要让“高级”变成延迟看见商品、追逐鼠标或强制看完动画。

## 每次都要完成的内容职责

这些是内容和功能要求，不是排列顺序：

- **Header 与公告**：真实菜单、Logo/shop.name、搜索、账户、购物车、本地化。保留已有菜单链接；公告简短、真实，无虚假倒计时。没有免运规则时不用免运承诺。Header 可改变尺寸、分布和视觉，但图标必须对应实际功能。
- **主视觉**：商品定位清楚，有适合当前品类的主图和明确购物去向。链接可编辑，默认使用本地化 All products 路由。标题长度、位置与图片关系由设计决定，不复用家居口号或上次的标题公式。
- **真实商品与分类**：执行 [csv-and-home-catalog.md](csv-and-home-catalog.md)。默认 8/4 空占位是店主确认的数据流程；不意味着 8 个假商品，也不决定画框样式。主商品网格默认桌面 4/手机 2 列。卡片媒体比例、边框、留白、信息密度可随本次设计变化；多变体先选项，不能自动买错。
- **服务与指导**：准确表达品类、Shopify 原生结账和联系帮助。FAQ 可编辑、可折叠、键盘可用，可调整位置和视觉。通用问题覆盖追踪、处理、修改/取消、损坏与联系；品类问题依据真实资料。没有资料时不写死时效、国家、保修、性能或退换承诺。
- **第二场景与品牌内容**：至少另一张独立摄影风格图。品牌叙事须有真实资料，没有则通过商品选择和场景建立气质，不编年份、团队、工厂、公益项目或认证。
- **Footer 与可编辑正文**：执行 [footer-and-policies.md](footer-and-policies.md)，保留服务、物流、售后、付款及相关政策的适用可编辑正文；正文职责不要求全部成为可见链接。精品严格复刻按本次截图的栏目、名称、数量、顺序、布局和开关，包括已明确开启的 Newsletter；其他任务保留原默认。Reviews 默认关闭，不造社会证明；空菜单无栏目，示例/无效社交链接清理。

## 图片由版式决定

先明确主图用途与候选构图，再共同确定素材和画框；图片与成熟布局不匹配时做必要局部适配，不强塞比例。8:3 Hero、3:2 场景、右侧产品左侧留白只是可选案例，不是长期默认。

**区分拉伸与裁坏，两者都须修复。** 压缩／WebP 转换前处理图片方向，保持原纵横比；只缩放时不能分别指定不成比例的目标宽高。需要裁切时另存明确裁切版本并看实际成品，不把改后尺寸当作原图。HTML width／height 写真实图片比例，多尺寸 srcset 的描述与实际尺寸一致，不能给全部素材硬写同一组宽高。

商品图优先完整展示，用 contain 或自然高度保持鞋、衣服、包、工具等真实轮廓；采用 cover 的编辑／场景图须按当前图片单独核对画框和焦点。禁止所有人像统一用靠上焦点，或把窄竖人像压进宽横框，只留下额头、眼睛、局部肢体而看不到服装／商品。先改成适合的竖框、改用合适横构图素材，或按真实主体微调焦点；严重比例不匹配时单改 object-position 不算修复。不得用不匹配的别款照片补空白。

Hero 每一帧、生活图、分类图、专题和商品图都要看原图及实际桌面／平板／手机裁切；主体、面部或商品重要部位完整、比例自然且符合栏目用途。需要独立手机构图时提供 mobile image picker，店主自选图保留原生 focal point 或可编辑焦点；画框跟随所在模块，不用一个全局规则覆盖所有图片。临时位移、scale 或固定双轴拉伸不能当裁切修复。仅文件尺寸、无溢出和 object-fit:cover 存在不代表验收通过。

至少两张独立、高清、商品清楚的摄影风格场景图。轮播的全部帧、Hero、生活场景及主要分类／编辑图须与其他站采用不同源照片；改名、裁切、翻转、调色、压缩不构成新素材。同站桌面／手机派生图可归同一素材族，跨站不能重新分配。按 [site-diversity.md](site-diversity.md) 检查本批和可访问历史，不仅比较第一张 Banner。自然可信的光线、材质与环境比滤镜更重要；按品类可用明亮户外、棚拍、街景或生活场景。只参考布局时不自行移植参考站素材；用户明确要求抓取图片时优先使用相应真实场景/模特照片及商品媒体，核对来源与实际内容，不把商品的自然品牌标识升级为官方店铺身份。无品牌站的场景和陈列图逐张筛除明显 Logo、品牌标识、文字、水印及可识别品牌款，不通过抹标伪装通用品；商品卡片持续读取真实 Shopify 媒体。

Banner、生活场景、分类和编辑陈列图默认从互联网寻找真实照片，不自行生成，也不因暂时没找到照片改用生成工具。优先有明确商用许可的图库或本次获准使用的来源，记录原图页面、图片 URL、作者及许可依据；不可只凭图片可下载认定可商用。只有用户后来明确要求生成时才走生成流程。两种情形都实际看图，核对主体、商品可见性和品牌／文字／水印。Pillow 等工具可用于 WebP 转换、压缩、尺寸和明确的裁切；检查细节、商品轮廓及手机焦点。独立手机构图可另配 image picker，不把桌面叠字直接缩小。默认图片打入 assets，上传即可加载，自定义图使用 image_url/image_tag；提供宽高、正确 sizes/srcset，首屏主图优先加载，下方懒加载。

## 手机是另一种编排

手机可将图外标题转为先图后字、重排双图优先级、简化导航和留白，不能只把桌面两列垂直堆叠便结束。避免长文案先占满数屏才看见商品；商品主网格保持两列，购买与分类入口易触达。横向列表须有清楚的溢出提示与可访问控制，不能截掉价格或把滑动当唯一发现入口。

## 交付前的视觉判断

实际看首屏、商品区、分类区、FAQ/服务与 Footer 的桌面和手机截图，并用空店与有商品两种状态检查构图是否成立。

- **构成**：有明确视觉主次与疏密变化；每段不都相同高度、相同图文比例、相同“标签/标题/说明/按钮”。
- **差异**：基础与自主设计仍对照近期作品，排除只换色、换图和翻转左右；遮住店名与图片仍高度相似时调整主要构成。精品核对成熟基线的保留质量与局部适配，不因布局相似强改首屏、购物入口或页面节奏；图片与商品仍须分别去重。
- **精致度**：容器/基线/边距、字级和换行自然，产品媒体稳定，图标一致，细线与按钮状态完整；大字和不对称不掩盖实际商品。
- **交互质感**：所选效果帮助辨认商品或操作，快进快退均顺畅，图片与文字不跳动；鼠标、焦点、触控、加载中、失败和禁用状态完整。实际操作检验，不能只看静态截图。
- **色面**：按本次方向检查深色、强色与浅色的主次关系和文字对比度；精品可保留成熟基线的浅色主体，其他模式仍避免都回落到白／浅灰主地。保留当次明确的品牌色限制和圆角边界，不靠复杂渐变、密集徽章、强制动效或浮层制造个性。
- **可用性**：对比度、焦点、触控、减少动态效果偏好正常；文字不重叠，图片不误裁，页脚确实出现。不能因功能测试通过就宣称视觉精致。

审美评审写简短实际结论与必要修正即可，不伪造自动“精致度评分”或跨品类统一相似度阈值。某个项目的特定行数、Hero 高度和模块顺序不能变成后续所有主题的测试断言。
