# 跨站图片唯一与整站设计差异

适用于后续单站、批量站，以及明确要求翻新的历史站。图片与真实商品去重适用于全部模式；布局变化按模式处理。**精品执行成熟基准优先、约 85% 保留／15% 局部适配的最新偏好**，允许沿用用户认可的精品布局、导航、卡片和详情组件，不要求逐站大幅重构；基础与自主模式继续形成实质构成差异。此精品规则优先于早先所有模式都须重构版式的要求。各模式均不以差异化省略购物功能或必要政策。仅更新技能不自动改写历史成品。

## 店面照片不能跨站重用

- 范围是 **Hero、全部轮播帧、场景图、分类营销图、专题／编辑陈列图，以及全部商品卡片、PDP 图库和变体照片**，包含桌面、手机、懒加载、备用图，以及模块删除重加会启用的 defaults／presets。不能只换轮播第一帧，后几帧和生活场景继续用同一张。
- 同一来源照片或素材族，无论改名、转换 WebP、压缩、裁切、翻转、调色、加遮罩、改变叠字，都仍是同图，不能分配到不同站。相同来源 ID、原图内容或可靠近似命中均应核对；不能换一个 CDN 尺寸 URL 就当作新照片。
- 同一站桌面／手机和多尺寸派生图可属于同一素材族，用 `parent_source_id`／`source_id` 和 `responsive_group` 关联；同站不同轮播帧不能用这些字段掩盖重复。单站后续修订可保留自己的图片，但不能把历史站的 ID 改名后重新占用。
- 商品卡片和 PDP 图库必须匹配真实 SKU，不能通过随意换图掩盖商品重复。同款按 [catalog-uniqueness.md](catalog-uniqueness.md) 归一站；同站该商品在卡片、PDP、分类预览中可复用原图。不同商品共用来源实拍图时也不能分到不同站：先核对是否实际同款，必要时成组分配或改选商品。支付标识、图标及必要品牌标识等功能素材不计入照片唯一性，不移除这些原生功能。
- 默认从互联网选真实照片，不自行生成；逐张核对品类、品牌／水印、真实可用性与使用依据，许可要求见 [design-and-content.md](design-and-content.md)。去重通过不等于已取得图片许可。素材不足时更换来源、主题场景或构图，不靠旧图裁切交差。

## 先规划每个站，而非循环复制一套组件

在工作目录为各站记录：首屏主构成、导航结构、首页模块节奏、分类入口、商品卡片、字级系统、整页色面关系、集合工具条／筛选、详情图库／信息区，以及选用交互。先看本批全部计划，再实现；选择在设计时固定，不在顾客访问时随机变更。

精品先记录所沿用的成熟基准，以及保持的首屏、购物节奏、导航、卡片、详情与手机行为，再安排独立照片、配色、文案和少量专题／陈列变化。不强制改变每个站的首屏结构、布局顺序或明暗分区；成熟结构相近时检查的是细节保留和品类适配，不为区别堆积动画、浮层或无用内容。

基础与自主模式仍应在**首屏构成、购物／分类陈列节奏、整页色面关系**上相对最相近作品作出实质区别，再让字体、卡片和内页跟随同一方向。满幅／双幅／拼接／商品索引是可选手法，不做几个风格代号循环；不同照片、标题或左右翻转不能独立代替其结构变化要求。

基础站／精品站继续覆盖完整的导航、首页、分类、所有卡片场景、PDP、搜索、购物车、服务与手机。精品按最新低改动偏好，把实际保留的设计轴记入 `locked_reference_components`，在 `reference_lock_reason` 说明成熟基准、用户要求提高旧精品权重的依据及实际保留范围；无需每次让用户重复锁定。其余模式的锁定仍须有相应明确指示。不能只改描述或虚报全轴锁定来消除报警；未逐项还原的成品不宣称像素一致。

## 历史记录与本批全量查重

素材和设计记录保存于本次**工作目录**，可以维护不含商家个人资料的本地历史索引，分享技能时不内置任何旧店身份、账号或素材授权假设。记录应包括站点唯一 ID、素材角色、公开来源页／照片 ID、许可依据、原图与成品文件、多尺寸关系及实际交付目录；可复用旧站自己的记录做修订。

历史比较覆盖所有可访问的既有关键图记录，不限最近三站；当前批次全量两两比较。`inspect_design_history.py` 只辅助发现直接子目录的部分记录，不能证明已检查嵌套目录或 ZIP 成品。如果只有历史 ZIP，在工作区只读解包，结合 layout、JSON 模板、section group、保存配置和 Liquid／CSS 中实际启用及备用的图片引用，补录相关素材。不要把未引用的备份图当作实际轮播，也不要只扫描文件名便声称查过主视觉。

没有历史登记时，首次执行应在可访问范围内补录；无法访问的旧记录／图片单列未检查范围，不能声称对全部历史保证不重复。本次任务仅更新技能时不去重写原来的成品。

### 本地查重命令

```text
python scripts/audit_site_diversity.py --plan WORK/batch-design.json --history WORK/history-assets.json --report WORK/diversity-audit.json
```

`--history` 可重复提供；不联网，不自动修改主题、图片或历史索引。该脚本只检查营销图和设计，不检查产品目录；另运行 [catalog-uniqueness.md](catalog-uniqueness.md) 的目录审计，涵盖商品、详情和变体图，并把营销照片放进同一全图片清单，检查跨角色复用。路径相对各 JSON 所在目录解析。最小结构为 `{"sites": [...]}`；每站形如：

```json
{
  "site_id": "batch-a/site-01",
  "mode": "premium",
  "design": {
    "hero_composition": "双幅专题，图外短标题",
    "navigation_structure": "主分类横排与独立搜索",
    "section_rhythm": "专题、分类索引、商品、使用场景",
    "category_presentation": "不等宽照片索引",
    "product_card": "紧凑信息，真实辅图与选项",
    "typography": "衬线标题与清晰无衬线正文",
    "surface_structure": "深色主地、浅色商品面、单色专题",
    "collection_layout": "侧栏筛选与四列商品",
    "product_layout": "缩略图图库、独立购买栏与参数披露",
    "interactions": ["辅图淡切", "分类预览", "购买状态反馈"]
  },
  "images": [
    {
      "role": "hero",
      "source_id": "provider:photo-unique-id",
      "source_url": "https://example.org/photos/photo-unique-id",
      "path": "site-01/theme/assets/hero-desktop.webp",
      "parent_source_id": "provider:photo-unique-id",
      "responsive_group": "hero-a"
    }
  ]
}
```

列出全部关键图，不只示例的一项；手机图和其他轮播帧各有记录。`source_url` 仅放公开、无凭据且指向具体原图／照片详情页的 URL，不能给所有素材填同一个图库首页或搜索入口。已确认同一站修订时，在站点记录填 `revision_of` 为原 `site_id`；这只表示同站迭代，不允许另一站借相同 ID 跳过检查。

脚本使用来源标识／规范化 URL、文件 SHA-256；有 Pillow 时补解码像素指纹和近似候选。完全相同的已解码像素可识别无损换格式，JPEG 等有损重压缩通常只能列近似候选，任意裁切不保证自动识别。因此 **来源登记、自动检查与实际看原图／全部轮播帧缺一不可**，不能把哈希不同当作新图证明。

退出码：`0` 为该清单范围内未发现自动阻断；`1` 为清单错误、精确跨站重图或未获保留授权的完整设计签名重复；`2` 为需实际看图／检查差异的候选或能力缺项。精品真实保留的结构通过上述锁定声明记录；脚本已有明确参考保留机制，不更改签名来冒充新结构，历史记录缺锁定造成报警时保留报告并结合当前授权人工说明，不伪改历史证据。锁定不豁免图片查重。精确重图须换源，近似候选逐对看图并记录判断。脚本不评判高级感，也不取代成品截图比较。

## 交付前看整批，不能只逐站单独过一遍

保存每站桌面／手机首屏、全部轮播帧和主要页面截图，制作本批并排概览，同时查看完整页面。精品并排对照成熟基准的字级、比例、密度、留白、卡片、详情与操作反馈，允许相近首屏／模块节奏；若改动后更空、更粗糙或比例失衡，应回退并打磨。基础与自主模式仍用遮住店名、照片及小面积强调色的方法检查结构差异。全部模式检查实际配色的文字／价格／表单状态与手机裁切。

逐站核对实际渲染的图片及 defaults／presets 与清单一致，测试轮播切换、触控／键盘、懒加载和失败回退；仅按文件哈希、首帧截图或 CSS 文件名不同不能通过。交付前将新站记录纳入本地历史索引，文件和图片路径需在后续可找到；工作记录留在工作目录，最终目录按主技能交付 ZIP、CSV 和一张本站首页截图。功能、政策、价格、库存、原生付款和可编辑性继续按原验收流程完成。
