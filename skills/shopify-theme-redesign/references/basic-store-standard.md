# 基础站：EstateKid 整站高还原标准

## 模式与参考

用户称“基础站”“基础模板”时，默认以 [EstateKid](https://estatekid.com/) 为整站完成度和精细度基准；本次明确指定的新视觉参考优先。基础站不是低保真、简化功能或只做首页，也不是直接交付 `native-base.zip` 的外观。精品站另按 [精品标准](premium-store-standard.md) 处理 Cozyster 的适用职责；各模式默认采用 [跨站差异和关键图去重](site-diversity.md)，本次明确锁定的组件才原样对照。

以对应参考的密度、排版精细度、商品卡片、详情和手机完成度为基准，同时按站间计划独立组织首屏、陈列节奏、色面和内页。共用默认参考不再允许整批直接复制相同视觉系统；差异化不能简化购物功能。基础模式不自动继承 Cozyster 的专题、底部工具栏、完整快速查看等组件义务；依据本次参考的实际实例和交互确定。

视觉参考与商品来源分开处理。采用 EstateKid 外观不自动授权抓取其商品、图片或经营资料；商品范围和素材使用按本次任务及主技能执行，不移植参考店身份。

## 观察与复刻方法

先读 [EstateKid 观察记录](estatekid-layout-study.md)，再确认本次参考的可访问页面和状态。现有 HTTP／HTML／CSS／JS 证据不等于全部桌面、手机和交互已经实测；公开页面也不能恢复完整 Liquid、schema 或后台配置。只把已观察事实写入复刻依据，未见状态列待核对。

建立对应的页面／状态清单，记录视口、模块顺序、容器宽度、网格和间距、媒体裁切、字体与字级、按钮／边框／圆角及交互触发。本次明确锁定的参考组件按实际观察优先还原；其余视觉按本站差异计划实施。真实数据、已确认经营规则、原生功能和可用性约束持续保留。

参考已有且适用的组件应实际重建，不能因为功能底稿没有就省略，也不把底稿原来的 Hero → 服务条 → 商品 → 生活场景 → FAQ 当作基础站成品。按本站差异计划组织展示，锁定组件单独还原；关键状态未见或原生边界造成差异时，完成可确认部分并记录差异，不沿用未核实的成功结论。

## 商品卡片与购买行为

- 全部卡片使用场景都核对当前商品、标题、媒体、双价和可售状态。首页有合适真实辅图时还原对应 hover／focus，手机按参考的横滑和触控规则处理；单图、无图和辅图失败保留稳定可读的主状态，不造第二张商品图。
- 原生卡片的轮播、选项和 quick-add 按参考适用行为重建。单规格与多规格路径分开，选项读取完整真实组合，不随机买入首个变体；源站未出现的快速查看不强加，事件钩子本身也不算已实现。
- 各处商品链接与独立操作不冲突，长标题、不同位数价格、徽章和翻译不挤压邻卡；轨道、集合、搜索及空车陈列分别检查宽度和数据，不能只验首页一张卡。
- PDP 主表单和吸底表单同步当前变体 ID、价格／划线价、媒体、库存／可售、数量 min／max／step。选择组合、无效组合、售罄、库存变化和加入失败有真实反馈，支持完整购物车及原生结账回退。
- 实际参数、材质、尺寸、养护和指南取当前商品资料。参考的鞋码、服装尺码及折扣不套给其他商品；购买附近的配送／退换说明取本站确认底稿。
- 对菜单、搜索、媒体、快捷购买、吸底栏和抽屉实际检查鼠标、键盘、触控、焦点与关闭恢复、慢载／失败、减少动态效果和 Theme Editor 重载。不能因源码有播放器、预测搜索或推荐组件就称运行成功。

具体实现边界参见 [零售交互](retail-interactions.md) 与 [整站职责](storefront-depth.md)，同时执行站间差异；用户本次明确锁定的参考组件单列保留，不作为整站重复母版的理由。

## 已确认规则与系统边界

- 默认每站从 10%、15%、20%、25% OFF 四档随机选择一次后固定，按 [双价规则](pricing-and-promotions.md) 逐规格落实，参考原价必须有效，不能把参考站不同折扣、首页无价格或只有单价复制成本站缺陷。没有目录或价格依据时不虚挂已生效优惠；不在前台或结账重复打折。
- 经营者、地址和获准公开的联系方式仅取本站资料；缺必要事实保留明确 `#待填入`，不复制源站 Logo、身份、邮箱、营业承诺或品牌历史。政策继续用已确认的退换、配送、退款和 15 分钟取消底稿，不因复刻更换经营条件。Reviews／Newsletter 仍默认关闭。
- 保留 [Footer／独立页面规则](footer-and-policies.md)：正文在包内可编辑，缺后台 Pages 时明确待配置，不造链接；上传 ZIP 不会创建 Pages。语言、国家及对应货币用 Shopify localization 真实选项，单选显示当前值，不用静态 US 或假换汇替代。外部追踪链接不证明已集成订单物流。
- 空店保留既定中性商品／分类预览，真实商品导入后自动替换；不补假 SKU、示例推荐、销量、评价或历史。真实有数据后的卡片不留示例占位。
- 原生商品、购物车、搜索、账户及结账接口、可编辑模块和既有设置继续保护。复刻不授权后台发布、修改支付或处理订单；交付目录和 ZIP／CSV 份数沿用主技能，不增加安装文件。

## 验收与交付表述

在工作目录列参考页面、实际观察、各卡片使用位置、已对齐项、必要适配和未观察状态。用相同视口的参考与成品逐处比较布局、字体、颜色、间距、图片裁切及交互，修正桌面、常用手机与 320px 易挤压状态；同时对照本批和最相近历史作品；除本次明确锁定的组件外，只换图换色而构成相同需调整。按参考核对完成度，按站间计划核对区别，两项分别记录。

按 [验证与交付](validation-and-delivery.md) 完成静态、官方检查及可用的真实预览，覆盖单图／多图、长标题、单／多规格、不同价、售罄、缺图、空数据及加载失败。功能核对与视觉对照分别记录；HTTP 200、源码存在、检查通过或自动相似度不能代替实际看图和操作。未完成视觉或交互验证时明确待验，不称已完成高还原验收。

本标准是后续创建与验收要求，不证明准备脚本已生成 EstateKid 展示层，也不代表旧 ZIP 已升级。仅更新技能时不顺带修改历史成品；局部修复仍只处理本次授权部件及受影响依赖。主题草稿、后台保存、实际商品导入和线上配置分别说明，不将本地交付称为整店已上线。
