# 精品零售交互与 CSS 细节

各模式按本站商品与 [站间差异规范](site-diversity.md) 实现协调的 hover、换图、快捷面板、图库、吸底栏与购物车反馈。精品优先保留成熟精品的可靠交互及精致尺寸，只按媒体和规格做必要适配，不为跨站差异重造主要购物组件；基础与自主模式按本站方向变化。不把另一参考的全部交互强加进来；真实商品、性能、键盘／触控及失败回退仍须保留。

## 每站形成自己的操作气质

精品以成熟交互为主，允许真实辅图切换、快捷购买等行为跨站复用，局部选型随真实商品适配。基础与自主模式继续主动选择有本站特点的效果。“随机接入”指设计阶段选择与微调，不是运行时随机卡片行为，也不是精品站必须每次换一套操作。

先看真实商品媒体、选项与购物任务，再选主次分明的交互。精品对照成熟基准打磨卡片、选项与反馈，相近构成和行为不强制触发重构；基础与自主模式再检查是否只有过渡时长或色号变化。无需每店完全发明新交互，不为避重放弃可靠的购买习惯。

在已有设计记录里简述选用效果、与商品的关系、手机/键盘/静态回退和相对近期作品的变化。不会改善浏览的效果可以不加，不按固定数量、固定轮换风格或每区一个动画机械配置。

用户进一步要求交互丰富，不能把“克制”解释成整站只有一个 hover。阅读 [本地 CSS 交互知识库](css-interaction-knowledge.md)，为导航、分类、商品、披露、购物车和客服补齐有用的操作状态。精品复用成熟操作体系并小幅打磨，其他模式按其方向组合主次；完整细节优先于动效数量。

## 可组合的手法

下面是可选设计资源，不是所有站必须装上的组件包。

| 场景 | 可实现的细节 | 选择与边界 |
| --- | --- | --- |
| 服装、包、鞋有多张照片 | 商品主图与真实背面、侧面、上身或细节图轻淡切换 | 静态可见主图；辅图与该商品一致。若第二张只是重复正面，优先采用更有信息的后续图。 |
| 商品卡片需要保持清爽 | 媒体下沿显现快速购买/选择选项，边框或信息线同步反馈 | 不遮挡标题、价格；键盘也能操作；触控端始终提供清楚入口。多变体先选项。 |
| 服饰存在真实尺码或其他简短规格 | 卡片显式展开可售选项，桌面可随焦点/hover 提示 | 读取当前商品实际选项和 available 变体，跳到正确 variant 或显式选择面板；不是所有品类必装。 |
| 多品类分类索引 | 焦点/悬停分类名称时更新旁侧对应照片，或轻微改变卡片裁切 | 只切换预览，点击进入真实分类；手机用可见图卡，不依赖悬停发现分类。 |
| 器材需要比较 | 展开真实规格、两图对比或局部细节面板 | 有数据才展示，提供明确关闭/收起操作；不虚构参数，不让全卡点击与内部按钮冲突。 |
| 系列或专题入口 | 图片轻微放大、边缘标签/箭头短距离移动、链接下划线展开 | 保持图片边界、文字对齐与阅读稳定；不全站每张图同时放大。 |
| 横向专题目录 | 原生滚动与 scroll-snap、上一项/下一项控制及当前位置反馈 | 主商品网格仍默认桌面 4/手机 2；不劫持页面滚动，不把拖拽作为唯一操作。 |
| 导航和筛选 | 对应栏目指示、克制的展开过渡、筛选状态与数量反馈 | 使用真实数据和原生路由；展开可键盘操作、可关闭，不能挡住主操作。 |
| 页面内容衔接 | 局部、轻量的一次性进入反馈，编辑式分隔或线条变化 | 内容默认已显示，增强加载失败仍完整；不把每个 section 变成同一套上浮渐入。 |
| 长商品页购买 | 主要购买区离开视口后显示当前规格的吸底操作 | 双价、库存、数量及按钮状态与真实表单同步；不能覆盖内容或购买错误规格。 |
| 手机购物路径 | 按需提供首页／搜索／分类／账户／购物车底部入口 | 真实路由及数量，处理安全区和键盘；与吸底购买、抽屉和隐私提示协调，不强制每站同一底栏。 |
| 空购物车导购 | 从当前店真实集合展示少量可售商品并提供目录入口 | 数据为空则退回有效购物入口，不显示假畅销、示例商品或伪造推荐理由。 |

正规与高级感靠完整排版和反馈体系：对齐、留白、字级、媒体比例、焦点、按下、等待、成功和失败状态。不要用伪造销量/折扣/稀缺库存、认证、抢购弹层增加“可信度”。避免跟随鼠标的大光斑、晃动、旋转翻牌、复杂光泽、自动轮播、全屏强制入场和滚动劫持。用户本次明确指定的创意另行判断。

## 商品辅图切换的实现约束

- 主图来自当前商品真实媒体。辅图从 `product.images` 选择与当前主图不同的图片；明确关联到所选变体时优先保持该变体一致，不能把另一颜色/款式伪装成同一选项的细节。不要把 `product.media[1]` 默认当图片，媒体还可能是视频或模型。图片不足时保留完整单图卡片，不显示空白辅图、假细节或临时生成的 SKU 图。
- CSV 抓取任务保留源站可用的多图及正确 Image Position，不为新增 hover 把全部商品图片下载进主题 ZIP。Theme Editor 上传新商品图片后同一逻辑继续适用，不依赖写死 URL 或当前抓取清单。
- 媒体框预留 `aspect-ratio`，图片有宽高与响应式 `srcset/sizes`，两图使用一致边界与适合品类的 `object-fit`。用 opacity/transform 反馈，不动画改变卡片高宽或价格位置，不使用 `transition: all`。
- 用 `(hover: hover) and (pointer: fine)` 限定鼠标效果。聚焦卡片链接/操作时给清楚的 `:focus-visible`，适当支持 `:focus-within` 预览，但不让键盘焦点消失，也不嵌套链接/按钮。手机点击一次即可执行明确动作，不能第一次点击只触发 hover、第二次才进入商品。
- 主图始终可用，辅图成功加载后再标记为可切换；失败或未加载时不先隐藏主图。CSS 淡入可将辅图叠在主图上，避免两图同时透明而露出背景。装饰性辅图不重复朗读主图 alt。
- 首屏关键商品图按实际首屏优先级加载；辅图按接近视口、焦点或 hover 意图加载，选择与目录规模相称的方案。不预加载全目录两套大图，不给所有辅图设置 high priority；启用懒加载仍要实测第一次悬停，避免明显白闪或长时间无反馈。
- 商品卡片行为可通过语义明确的 Theme Editor 设置关闭或调整。只提供本次实际实现的选项，不把所有特效库做成冗长的后台选择器；有原主题时兼容原设置。模块重新添加后 defaults/presets 和保存配置应保持本次设计。

## 选用尺码/规格预览时

规格来自当前 Shopify product/variant 对象，不能写死 S/M/L、用产品标题猜尺码或把源站变体 ID 用到导入后的店铺。链接使用当前实际 variant.url 或按当前实际 ID 构造本地产品 URL，并验证打开后选中了目标规格；不是仅检查 URL 含 variant 参数。多个颜色共用尺码时，保留组合语义，不能误示所有颜色均有该尺码；无法清楚表达时转到完整选项页。

展示真实可售项并去重，空项不输出。显式展开控件独立于商品链接，禁止链接套链接或按钮套链接。手机提供触控/键盘入口；选项较多可限制可见数并提供清楚的 All/Choose options 原生去向，不把整块面板撑出图片或遮住邻卡标题。卡片尺寸、文字与购买入口仍稳定，关闭增强 JS 后原生链接/披露组件可用。

采用这种布局时除常规 375–390px 外，增加 320px 的实际展开检查；验证面板边界、长选项、点击正确规格和一击进入商品。相关标签放入 locales；减少动态效果、关闭设置和 Theme Editor 重载同样适用。不把本次的“前三项 + All”、媒体比例或配色变成每个新店的固定方案。

## CSS 节奏与渐进增强

常见短交互可从约 120–280ms 的 opacity/transform 过渡开始，再依据视觉检查调整；这不是固定验收时长。图片微缩放一般只需很小幅度，克制的平移、边线、字色和箭头变化常比整卡抬升/大阴影更合适。统一本店的节奏与缓动，重点组件可以有不同层级。

`prefers-reduced-motion: reduce` 下取消空间移动、缩放、自动滚动和非必要进入动画；必要的图片/状态切换即时完成，信息与操作仍在。不要用全局 `*` 粗暴覆盖现有主题所有动画或禁用依赖状态事件的组件；按所加组件范围处理。

默认 CSS 优先，加载就应可浏览与购物。确有需要时用少量原生 JS 处理图片就绪、显式展开或目录控制；不引入大型动画库、不持续轮询、不在每个 scroll/mousemove 中反复测量布局，不给所有卡片长期设置 `will-change`。Theme Editor 的 section load/unload、block select 和重排后重新生效，事件初始化幂等并可清理。

## 与所选效果匹配的检查

不用为本次未采用的效果制造通用测试。已采用的交互应实际操作，记录到本次预览检查结果：

- 多图卡片鼠标进入/离开及快速跨卡片移动，辅图正确且没有空白闪烁；覆盖单图、无图占位、辅图慢载/失败。主图和商品链接持续可用。
- Tab / Shift+Tab / Enter / Space 适用路径、可见焦点、展开/关闭和快速购买；按钮不触发外层跳转，不误买首个变体。
- 手机/触控不依赖 hover，无粘住浮层；主商品两列、长标题、价格及购买入口不挤压。辅助操作显现不改变网格高度。
- 开启减少动态效果、关闭相应设置、未执行增强 JS 时，内容与购买路径仍正常。按实际交互需要测试，不把静态截图当作 hover 已验证。
- 检查图片请求与页面移动：不下载全目录辅图，不因 hover 产生明显布局跳动；修改/重加 Theme Editor 模块后没有重复监听或失效。

实现依据：[Shopify product/images](https://shopify.dev/docs/api/liquid/objects/product#product-images)、[MDN hover 媒体特性](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/hover)、[MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)。这些文档说明能力与媒体行为；复刻模式按参考对齐，自主模式独立选择构成和效果组合。
