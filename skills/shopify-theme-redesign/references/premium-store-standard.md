# 精品站：整站高还原复刻标准

## 约定与范围

用户称“精品站”“精品模板”或沿用本套精品流程时，采用完整精品零售标准，无需逐项重复商品卡片、详情页和手机端要求。优先级为：本次明确的新视觉指示 → 用户认可的历史精品成品 → https://www.cozyster.shop/ 成熟精品基准。没有指明具体历史文件时结合可访问成品、截图和记录确认适合本品类的成熟版本，不把最近生成的一批自动当作用户认可版本。

**默认约 85% 沿用成熟精品的布局与组件关系，约 15% 做局部适配。** 此比例是改动范围的设计取向，不是代码行数、像素相似度或自动验收分数。保留首页购物节奏、导航层级、容器与媒体比例、卡片信息关系、分类工具条、详情图库／购买区、Footer 与手机端细节；独立照片、配色、文案、真实分类及少量专题／陈列变化承担站间特点。不为凑差异重排整页、强制不对称、扩大留白或简化成熟组件。按 [跨站主图唯一与设计差异](site-diversity.md) 继续执行商品与图片去重，成熟结构允许复用。

[Cozyster 既有观察](cozyster-layout-study.md) 来自公开 HTML，并非全站视觉／交互已经验证。制作时仍须实际观察指定参考站；未见的状态、空容器和示例推荐不能凭空补成已知事实，不能仅靠 HTML 宣称高还原验收完成。

用户明确限制为局部修改时，仅处理该部件及受影响依赖，不借“精品”扩张成全站重做；历史成品升级也按本次指定范围。原生支付、订单、托管结账和新版账户边界不变。

## 复刻方法和优先级

- 建立参考页面与状态清单：桌面／手机导航、首页各模块、卡片静态／hover／快捷操作、分类工具条、商品图库／选项／吸底栏、搜索、空／有商品购物车和服务页。截图／操作状态明确记录视口，不把一个首页代表全站。
- 记录可观察的容器宽度、模块高度与顺序、网格列数／间距、媒体比例／裁切、字体家族／字重／字号／行高、按钮／边框／圆角及交互时机。默认保留成熟基准中协调的视觉关系，对照本次照片、字串和商品做小幅适配；无需用户逐项锁定才能保留。平台功能及真实数据约束不被覆盖。
- 参考站有的适用组件和交互是完成度核对项，不能因为基础包没有就省略或换成较简单的展示。按真实 Shopify 数据重建功能，再按本站计划安排视觉；关键状态未见、资料不足或系统边界造成的差异逐项记录，优先完成可确认部分。
- 以成熟基准保留购物层次、版式与可靠交互，仅按本站品类、照片和真实内容调整必要部分；在设计记录中列保留项与局部改动，而非要求每站另造主要结构。商品名称、品类术语、规格、图片和经营资料用本次真实内容；源图使用范围依本次授权、素材可用性与跨站唯一要求，不把参考品牌／店主身份装成本站身份。政策、促销及系统边界仍按本店已确认要求。
- 用同视口的参考／成品图逐处对照，修正首屏、卡片、详情购买区和手机端差异；实际操作 hover、快捷查看、变体和购物车。审美评分、自动相似百分比或“已很高级”的描述不能替代还原检查。参考不可访问或关键视觉未观察时，明确未核实范围，不声称像素级一致。

## 整站覆盖

| 页面／组件 | 精品站需要完成的职责 |
| --- | --- |
| Header／导航 | 品牌、真实分类、搜索、账户、购物车关系清楚；目录层级服从商品规模，桌面和手机均能找到完整分类，不只装饰首页菜单。 |
| 首页 | 优先保留成熟精品的专题／商品穿插、顺序、主构图、图像比例、字级与留白，仅对真实内容和少量陈列做适配；购物密度、整页质感与图像唯一持续保留。 |
| 分类／集合 | 标题与分类上下文、精致工具条、原生筛选／排序、活动条件、重置、数量说明和翻页形成完整界面；按需增加密度或每页数量选择，保留查询及本地化路由。 |
| 全部商品卡片 | 首页网格／轨道、集合、搜索及本次采用的推荐、最近浏览、空车陈列都纳入设计和测试。保持本店同一排版／价格／状态语言，按上下文调整密度，不遗漏内页。 |
| 商品详情 | 完整图库、当前规格、价格／划线价、数量规则、可售状态、真实购买及错误反馈；描述、规格、适用品类指南和物流／退换／联系入口易找。 |
| 搜索 | 初始发现、输入、结果、空结果、加载／失败及翻页有清楚路径；选用实时建议时使用真实结果，保留普通搜索回退。 |
| 购物车页／抽屉 | 空态和有商品状态都完成设计；规格、双价／真实折扣、数量、行价、总计、移除、更新错误和结账入口准确。适合时加入真实商品导购。 |
| 内容／服务 | About、Contact、指南、FAQ、独立政策页、404及适用的博客／账户主题页统一视觉和操作语言；仅填真实内容和获准公开的资料。 |
| 手机端 | 导航、卡片、筛选、图库、选项、购买、购物车、服务页全部成立；悬停效果有触控／键盘替代，浮层和吸底操作互不遮挡。 |

Footer 也要严格复刻本次截图中的可见栏目、名称、数量、顺序、布局和开关，不沿用旧功能底稿的十四项菜单。本次 Cozyster 图2按 Contact Information、Customer Service、Our Policies、Newsletter Sign Up 四列，两组各五个链接，Newsletter 开启；准确标题、顺序与缺页面处理见 [Footer 严格复刻规则](footer-and-policies.md#精品严格复刻的可见-footer)。未显示的必要政策草稿可编辑保留／归档，不自动追加截图外链接。之后更换参考时按新参考重新确定，不固定为这十项。

## 商品卡片标准

优先保留成熟卡片的媒体框、图片展示、商品名、双价、徽章、色样／选项、按钮和 hover／快捷面板的位置、尺寸与层级。按本次媒体和选项做必要适配，各使用场景分别完成，不只打磨首页卡片，也不为变化重新发明整套卡片。以下数据和可用性规则始终保留。

- 媒体来自当前商品，按本站设计计划预留比例和图像边界；本次明确锁定的媒体呈现按参考还原。换图使用本店合适的真实辅图，效果服从本站购物任务；单图或无辅图时保留清楚主图，不伪造第二张。无图使用诚实缺图状态。
- 商品名、真实售价、有依据的划线原价、可售／售罄状态及购买入口层次清楚。长标题、不同位数价格、翻译和徽章不会挤压邻卡；折扣来自当前规格，不拿不同规格的两项价格拼优惠。
- 单规格直接加入与多规格选择必须区分。颜色、尺码／规格按钮读取当前真实选项组合和可售变体；不能让顾客误买首个规格，也不能沿用源站的 variant ID。
- 快捷购买路径与参考适用行为一致。参考有卡片选项或快速查看时应实现对应真实功能，不默认用普通商品页跳转代替；慢载／失败和不适用组合才保留清楚的完整商品页回退。图片放大不冒充快速查看，表单、关闭及焦点恢复正确。
- 媒体链接、商品标题和独立操作的点击范围清楚，不嵌套链接／表单。hover、focus、触控、按下、加载、成功、失败和禁用状态协调，手机一次点击能执行明确动作。
- 所有采用商品卡片的页面使用同一套真实数据原则；复用组件后仍检查本站轨道宽度、手机网格、搜索结果对象和推荐数据，本次锁定的组件再对照参考。不能只验首页的一张卡片。

具体换图、加载和规格边界见 [retail-interactions.md](retail-interactions.md)，双价规则见 [pricing-and-promotions.md](pricing-and-promotions.md)。

## 商品详情页标准

- 图库使用真实产品媒体及所选规格关联，完成缩略图、主图、图库／购买区、查看大图和适用视频；布局按本站设计计划组织，本次明确锁定的形式按参考还原。图片加载失败仍有可读消息和稳定布局。
- 主购买区同步当前变体的价格、参考原价、媒体、库存／可售状态和真实提交 ID；数量符合 min／max／step。选项较多时用清楚的分组／选择器，不靠缩小字或挤出屏幕容纳。
- 加入购物车、等待、成功、售罄、无效组合、库存变化和原生错误都真实反馈；支持直接进入完整购物车及原生结账，不伪造成功。
- 描述、实际参数／材质／尺寸、养护、包含物等按可得资料组织。尺码／尺寸指南与该商品或品类相符，没有真实数据不编通用换算、适配能力、认证或保修。
- 购买附近提供可读的配送、退换、售后摘要与真实独立页面入口，事实取本店确认底稿。联系方式、身份和时效不从参考站搬用。
- 采用吸底购买时，核对出现条件、布局和适用的桌面／手机行为，按本站设计计划实施，本次锁定的组件逐项还原；与主表单的当前规格、双价、数量和可售状态同步。原生约束造成差异时说明原因和可用回退，不留失步的第二份表单。
- 完成适用的相关／搭配／精选陈列，数据来自实际推荐或有效集合，呈现按本站计划组织并排除不适用项目；没有结果隐藏区域，不为差异堆没有内容的模块。最近浏览仅用真实访问记录，评价应用需真实内容，均不输出示例卡、假销量或假历史。

## 高还原与既有约定

首屏构成、字体、色面、分类组织、卡片、详情图库和交互均记录成熟保留项与必要适配。相近版式不是精品模式的失败条件，精致度、整站完成度与内容适配优先于变化幅度；不照搬上一站照片、商品或经营身份。用户后续明确要求大幅自主重设计时再扩大改动范围，不在顾客访问时随机改变行为。

继续遵守已确认的经营规则、每站独立资料、原生系统与轻量实现。默认逐站从 10%、15%、20%、25% 四档随机选定并固定，优惠仅在原价依据及实际商品价格验证后启用；Reviews 默认关闭。Newsletter 的一般关闭默认在精品严格复刻时服从本次截图／明确指示，本次 Cozyster 图2须开启；使用真实原生表单，不伪造成功。空店允许现有的中性商品／分类预览和必要资料 #待填入，导入真实商品后自动替换；禁止的是假 SKU、假购买、假评价／推荐，以及有真实数据后仍残留的示例商品。

独立政策页、可编辑正文与后台 Pages 的边界沿用 [footer-and-policies.md](footer-and-policies.md)；ZIP／CSV 份数、目录命名和来源核对沿用主技能，不额外制造安装文件。

## 精品验收与交付表述

- 设计记录列本次适用页面、卡片使用位置、采用增强、真实数据来源及必要待配置项。基础包和已安装设计技能不能代替成品完成度，选用组件须在本轮实际实现。
- 复刻验收列成熟基准与成品在布局／视觉／交互上的保留项、局部适配、必要差异和未观察状态。桌面／手机对照成熟基准，若改动造成购物区变空、比例失衡或卡片／详情粗糙，回退并打磨；不为结构去重降低精致度。对照本批／历史作品继续核对商品与全部照片唯一。
- 功能核对和视觉评审都要完成。覆盖真实单图／多图、单规格／多规格、不同价、售罄、长标题、缺图、空数据和加载失败；看到一个成功页面不能替代其他适用页面／状态。
- 查看桌面、常用手机及 320px 易挤压状态，检查实际字体加载、断行、图片裁切、工具条、选项面板和 Footer；用真实行为测试键盘、触控、减少动态效果及 Theme Editor 重载。
- 同步验证卡片／快速查看／详情／吸底购买／购物车的数据和所选规格，复测相关浮层和购买错误。按本次变更重跑必要检查，不用固定通过项数量替代质量判断。
- 按 [validation-and-delivery.md](validation-and-delivery.md) 校验结构、官方 Theme Check、可用预览及最终 ZIP／CSV。明确本地模拟、实际视觉检查、后台保存与新包导入分别验证到哪一步；未完成视觉或动态验证时如实写待验，不称已达到精品验收。
- 主题完成度和店铺经营配置分开说明：必要身份待填、后台 Pages／Markets／收件等未配置时可以交付已明确状态的主题草稿，不称完整店铺已经上线。精品标准不授权额外后台发布、修改支付或处理订单。
