# 验证与交付

批量站额外执行 [商品与全图片唯一性](catalog-uniqueness.md)：最终 CSV 必须与逐站归族清单一致，真实款族和导出照片不能跨站共享。商品组合不同、handle 不同和文件哈希不同都不能代替真实款／原图去重；同时保留营销图设计审计及目录全图审计。数量不足先扩源并说明实际缺口，不把来源候选数当作已验收独立款。

用户要求基础站或精品站时，分别执行 [基础标准](basic-store-standard.md) 或 [精品标准](premium-store-standard.md)，逐页、逐卡片场景对照购物职责、信息层次和精细度，在相同视口检查桌面／手机。精品默认以约 85% 成熟布局保留／15% 局部适配为设计取向，重点核对顺序、比例、字级、色面、间距、卡片与详情关系是否保留精致度，不因结构相近强制重做；该比例不作为自动相似度分数。基础与自主模式仍按差异计划验收。各模式核对媒体、规格、双价、购买和原生状态，执行 [主视觉去重和分模式变化验收](site-diversity.md)。功能底稿、HTML 或单页静态通过不等于视觉验收完成；必要差异、未观察状态和待配置项分别说明。

## 静态与兼容

有原主题时对比原始文件与成品，检查没有误删系统文件、原商品 / 搜索 / 账户 / 购物车模板、app 接入、locales 和设置。自主构建时按 [reference-and-build.md](reference-and-build.md) 核对完整 Shopify 模板与功能，不虚构原主题对比结果；文件夹为空不是检查失败或要求用户补原主题的理由。

- layout/theme.liquid、templates/index.json 存在，首页引用的 section 与 order 正确，无冲突旧首页。
- 检查全部 JSON 和 section / theme block 的 schema。允许 Shopify 合法生成文件头注释；拒绝重复 keys、错误逗号、无效默认值和引用缺失。
- 区分 schema 默认值与保存值：可选 text／textarea／url／richtext 等字段不需要默认内容时省略 `default`，不要写显式空字符串；这不意味着删除合法的空保存值。按实际引用的 section／block 设置类型核对 templates、groups、presets 及 settings_data 中的值，richtext 正文使用平台支持的 HTML，不能把普通裸文本直接存进 richtext 字段。
- `settings_schema.json` 中 Brand 等普通分类保留原名称与 logo 等设置，不把 `theme_name`／`theme_version`／`theme_author` 挂到该分类上，也不假设数组首项一定是主题元信息。主题元信息可省略；需要提供时使用符合平台完整结构的独立 `theme_info`，不为满足格式编造支持邮箱或网址。
- 必须核对 select/radio 的默认值、presets 和保存值属于实际 options，并检查 section/block ID 不含空格或文案。已有原生 ID 的下划线/连字符要保留，新生成结构 ID 优先用字母数字。检查包含已禁用 section，因为导入仍会校验其 schema。禁止用整文件全局替换品类文案，防止同时改坏图标枚举和结构 ID。
- 检查平台服务端约束，尤其 inline_richtext 默认值不支持 <br>；本地渲染器宽容接受的 HTML 不能作为可导入证据。section/block/preset 名称采用不超过 25 字符的保守范围。有店铺访问条件时导入新草稿验证首页，不根据本地 200 推断线上通过。
- 一个 section 或 block 的 settings 数组只允许一个 link_list；额外菜单通过独立可重复 blocks 实现。检查 layout 引用的每个 section group 存在，group 指向的 section 与 block_order 有效，不能仅检查 index.json。
- 有原主题时核对原设置兼容；两条路径均核对颜色方案 schema / role / 数据实例 / 默认与保存引用 / CSS 输出，格式正确不能证明颜色方案可用。
- 如可用，运行 `shopify theme check --path THEME_DIR`，查看实际输出并修复新增错误。不可用时使用适当官方实现或明确未运行，不能称自制脚本是官方检查，不能自动上传来绕过检查。

辅助命令（Python 3 标准库，相对于技能目录）：

```text
python scripts/theme_audit.py THEME_DIR
python scripts/theme_audit.py THEME_DIR --zip OUTPUT.zip
python scripts/theme_audit.py THEME_DIR --zip OUTPUT.zip --max-bytes 50000000
```

脚本检查目录 / 必需文件、JSON、schema JSON、重复菜单选择器、layout 的字面 section group 引用、JSON 模板 section 引用 / order / block_order、结构 ID 字符及 select/radio 默认值 / presets / 保存值、显式空 schema 默认值、引用字段的 richtext 保存值、误挂到普通分类的主题元信息、颜色方案成对存在，再检查打包目录 / ZIP CRC / 大小。枚举检查包含已禁用模块。它不执行 Liquid，不完整校验 Shopify schema、动态引用、配置兼容、商品 / 图片 / 购物车 / 政策有效性。通过只能称“基础静态检查通过”；官方 Theme Check 无报错也不能代替这些导入约束及真实导入验收。

## 目录数据与本轮证据

涉及采集时，完成 [source-catalog.md](source-catalog.md) 的源快照、逐规格可售过滤、币种、图片全量可访问性及 CSV 往返核对。验证源集合成员 → 导出标签 → 主题分类映射的完整链路；大量分类不能只看前三四个入口，要核对运行时总数和循环边界，覆盖实际目标页标题、商品归属及分页。区分发现、扫描、保留、最终展示的各项数量。

本地对象模拟应与当前 Shopify 对象形状一致，例如真实图片对象含 ID/宽高、选项字段及当前变体 URL；搜索商品结果带正确 `object_type: 'product'`，实际核对卡片图片、价格与商品链接，不能误用文章/页面回退块证明商品搜索完成。JSON 模板和 section group 的 wrapper / section.id 使用 Shopify 动态 ID 形状，不能只用模板中的短 key 渲染后验收；布局不要依赖写死的 `#shopify-section-editorial` 等 ID。用稳定语义类或当前 `section.id` 定位，复测重命名/复制模块后的实际宽度、商品卡片及文字互不重叠，不能只凭页面无横向溢出判定布局通过。选取当前目录中的真实有图、多变体商品测试已选效果，再用独立边界夹具覆盖空店、单件、缺图、售罄等。若本地 Liquid 库不执行 Shopify 的循环上限，应补相应限制核对，不能因本地输出全部而称平台必定支持。

检查证据保留在工作目录：静态审计、实际官方 Theme Check 输出、预览行为/目录状态、所选设计交互、源数据与 CSV 关联、视觉评审和交付文件摘要。名称/格式可以变，不要求制造某个固定文件清单或通过数量。复用测试和打包脚本先去掉前项目品牌、目录、端口和固定计数；保留真实功能断言，不照搬旧报告。修复后重跑受影响的检查；若预览缓存了 Liquid、schema 或 locale，重启/刷新后再取证。

预览与检查运行时使用本次任务可用且稳定的依赖路径，复用时记录实际版本；优先环境提供的运行时或本任务固定依赖，不硬编码另一个可被移动、归档的旧主题工作目录。工具故障与主题失败分开记录，恢复依赖后补验尚未完成部分，不沿用未实际运行的成功结论。

涉及促销时按 [pricing-and-promotions.md](pricing-and-promotions.md) 从修改前原始数据独立核对本次所有 CSV：按本站已保存的固定折扣计划计算售价（新站默认 10% / 15% / 20% / 25% OFF）、划线价为有效原价，绝不在旧折后价上再打一次。确认所有参与变体正确、图片续行无价格、非价格字段未变，再启用本站准确百分比的优惠公告；核对卡片／详情／所选规格读取同一实际价格。未完成价格配置的纯模板不向顾客宣称优惠已经生效。

“所有 CSV”验收的分母来自本次完整成品路径清单，包含嵌套成品副本及每份 csv1…csv5；不能只抽查根目录、第一份文件或每商品第一规格。正价参与规格逐行验证售价与更高划线原价，区分空栏／零值／相等无效情况；已正确的文件保持原字节并计入验收，实际修正与未改文件分别报告。只改 CSV 时核对主题已有 compare-at 展示，不因此重写所有 ZIP；后台商品未实际读取或重新导入时，不把本地双价通过称为线上已显示。

本次要求促销时，向 `promotion_audit.py` 显式传本站 `--multiplier`， 联合检查最终 CSV 和主题。源价性质先验明；随后逐项看顶部启用的本站 **10% / 15% / 20% / 25% OFF**（或本次明确覆盖比例）文案、较高划线原价与本站倍率的现价、卡片／详情／规格同步及购物车实际金额。仅普通零售价或仅横幅不算完成，不能用某个不促销站的例外覆盖本次促销意图；图片或库存修复后也核对没有回退。未导入商品的纯模板与用户明确取消促销按其例外记录，不虚宣优惠生效。

批量修改旧包时先记录用户指定目录、原 ZIP／CSV 清单和哈希，保留原件，排除未授权目录；不照搬某批次的固定站数或文件数。全部新包／CSV 在工作目录验收后再替换，保留文件名和既有 CSV 份数。大量文件替换使用发布计划／进度记录和可恢复备份，遇到失败恢复已替换部分或明确记录需处理项，不在失败后只留下无说明的混合版本。最终核对落盘文件等于通过验收的版本，范围外文件未变。

### 类别与库存不能漏项

按 [商品类别与库存完整性](catalog-completeness.md) 对最终每份 CSV 运行 `scripts/catalog_audit.py`，按 handle 核对标准 `Product category`、`Type` 与主集合／分类映射，按每个变体核对 SKU、跟踪器、有实际库存或授权配额依据的数量、缺货策略及履约字段。新目录默认的随机虚拟配额另与稳定分配映射逐规格精确比对：全部为 60–99 整数、图片续行不伪造规格、重跑不改变既有分配；当前用户覆盖规则时按其要求验收。标准类别须匹配当期官方稳定 taxonomy，Type 有值不等于后台“类别”已填写。单地点产品 CSV 与多地点库存分开验收；available 不能证明数量，来源库存快照和授权虚拟配额均不等于已核实店主实仓。未获明确不跟踪例外时，不把 tracker 空或未知数量当作通过。缺项报告数量和受影响规格，不只核对表头；真实导入未验时明说。

## 实际预览

### 跨站主图与布局

各模式按 [site-diversity.md](site-diversity.md) 登记并检查全部轮播帧、Hero、主要场景／分类／专题图，比较本批全部站点及可访问历史素材，而非只看近期三站或轮播第一帧。精确重图须换源，近似候选实际看图并记录判断；清单须与当前渲染、备用图和 defaults／presets 一致。逐站看桌面／手机及内页，再看整批并排图：精品检查成熟基准保留与局部适配，允许有依据的结构复用并按参考锁定机制记录；基础与自主模式继续检查是否仅换图片、按钮色和文案。报告、素材索引和拼图保留工作目录。

使用本次有权访问的店铺 / 开发主题 / 预览，不发布生产主题。无访问权限时明确记录，继续本地工作。

- 打开首页根路径，确认实际页面非 404、Liquid error 或仅密码页；index.json 存在不等于首页验证通过。
- 图片真实加载且品类／栏目用途准确；查看源图及实际桌面／平板／手机画框，覆盖全部轮播、场景、分类、编辑图和商品图。缩放保持纵横比，HTML宽高／srcset与文件真实尺寸相符；cover裁切不截掉重要商品部位、不把人像裁成额头或眼睛。比例不匹配时更换合适素材或局部调整画框，不能仅凭文件尺寸、没有横向溢出或写了object-fit就通过。验证自选图片焦点、独立手机图和图片失败回退；保留实际看图与修正记录。
- 集合调用真实商品，标题、价格、可售状态和快速购买正确；覆盖本店存在的单变体、多变体、售罄情况。
- 验证“完全空店 → CSV 导入后有商品”两种状态：空店前台可见中性商品 / 分类占位，无假价或购买；同一首页配置加入可见商品后自动显示真实卡片并移除占位。覆盖有 Collection、有 Type、两者都无以及仅 1 件商品；分类链接指向实际集合或原生类型集合，不能用假卡补足商品数。具体流程见 [csv-and-home-catalog.md](csv-and-home-catalog.md)。
- 购物车可打开，正常加入、改数量、删除；结账入口沿用 Shopify，不提交真实付费订单来验证主题。
- 搜索、账户、已启用的语言／国家／对应货币选择可用。Footer 本地化检查双项可选、仅国家、仅语言、均单选／无可用数组、同币种多国家、多国家长列表及控件关闭；当前值、语言原名、label／form ID 不重复。实际提交 `country_code`／`language_code`，覆盖键盘及无 JS，不用本地 POST 模拟声称已经在线切换 Markets。
- Header 分类与首页实际集合/Type 联动；默认后台菜单不阻止自动分类，已有嵌套目的地保留且不重复。检查桌面横向主导航、手机分类捷径及展开菜单、长名称、当前项、本地化路径和空店不可点击预览；不将前台动态导航宣称为创建了后台 Menus。
- Theme Editor 可编辑、添加、排序、隐藏、删除，FAQ 正常，Reviews 默认关闭。Newsletter 一般默认关闭，精品严格复刻须按本次截图／明确指示保存开关，本次 Cozyster 图2为开启；核对真实原生表单及反馈，不把显示控件等同于已验证订阅送达。颜色无报错，保存后仍生效。
- 按 [配色与色面构成](color-and-surface.md#配色质感与文字清晰度) 查看约375–390px手机、768px平板与1440px桌面，长标题、导航、FAQ、页脚及其他实际语言无重叠、溢出、遮挡、焦点丢失。普通文字包含辅助字、现价／划线价、占位和按钮字至少4.5:1，大号文字按适用定义至少3:1，必要控件／图标／状态视觉部分与相邻色至少3:1。测浏览器最终颜色并合成祖先opacity、透明表面和底色；图片叠字检查每一帧及手机裁切。展开菜单、筛选、快捷查看、购物车、本地化和表单，复验默认／hover／焦点／选中／错误；发现同色字底或低透明隐字必须修复。记录实际覆盖和代表性测量，不以静态色板、Theme Check或配置中的白字宣称可读或整站合规。
- 实际展开新增卡片面板、导航和选项，不只检查折叠截图；尺码预览等易挤压组件补 320px 边界，具体按 [retail-interactions.md](retail-interactions.md) 检查。保留完整选项去向，验证链接到目标页后实际选中正确变体。
- 检查页脚每个入口与正文，空栏目、示例社交、假联系方式消失，品类指南与实际商品一致。服务／政策是普通页面链接，点击后 URL 和对应完整正文正确，无 JS 也能跳转；不遗留政策 dialog 或点击拦截。测试菜单与文档重复目标去重、本次允许的独有链接保留、空列隐藏，精品严格复刻不因独有 URL 而追加截图外入口；原生地址／app／支付图标保留。完整正文仍在 ZIP 的 schema/presets、保存配置及当前内容清单中；未知后台 Pages 要明确待配置，不能伪造路由。用户允许的后期字段标记 #待填入，不能以缺 Pages 为由省略包内正文。
- 精品严格复刻另逐项对照本次 Footer 截图的可见列、标题、链接名称／数量／顺序、布局与默认开关，不用十四份正文的清单代替截图。本次 Cozyster 图2按 [四列／十链接／Newsletter 开启](footer-and-policies.md#精品严格复刻的可见-footer) 验收；不自动增加截图外政策链接。未显示的必要正文核对可编辑草稿／归档是否仍在，缺真实页面的入口只标待配置，不能称已上线。之后换参考重新取清单，不固定套用本次数量。
- 对照 [merchant-policy-defaults.md](merchant-policy-defaults.md) 和本次目标店已确认规则检查所有政策/FAQ/商品提示。只把实际未知且必要的事实待填，不遗留来源站主体、1 小时取消、未授权最终销售排除、旧费用或原基线的大量填空。30 天从每件收货起，退款 5 个工作日从批准起，取消限未履约商品 15 分钟；不能混淆起算点或把预计运输写成保证。
- 使用本次真实个人经营者姓名及证件地址，检查 Footer、内置联系信息／法律声明与当前资料一致，默认值、presets、保存设置及内容清单无旧店身份或地址；缺姓名／地址才保留明确 #待填入。检查换行、长文本和 HTML 转义、共享 operator_address 内置展示；独立 Pages 正文另核对，不能承诺与主题设置同步。账户邮箱、凭据和身份编号不得公开；原生联系表单前台、原生错误反馈和后台实际收件分别验收，不造空邮箱栏。检查原生政策覆盖与本次公开资料一致；隐私实践／必要披露未核对时不称全部可发布或合规。
- 核对当前站点与本次店主资料的绑定，扫描正文、presets、保存配置、素材说明与导出中的跨站残留；不得把上个项目的姓名、域名或联系方式带入。当前资料缺失时应待填/询问，而非由历史任务自动补齐。资料的唯一性是任务归属要求，不是伪造身份的理由。
- 单独确认有可见 Footer，Theme Editor 也有 Footer 分组及可编辑文档。无后台菜单／Policies／Pages 时，完整草稿仍保存在包内，入口是待配置而非假链接；有实际已发布页面后正常跳转。覆盖 Page 覆盖、隐藏／未来发布页面、非空原生政策优先与空正文不采用，不能只检查建议 handle 字符串存在。
- 所有模式核对底部支付图标区：默认、preset、保存配置均开启；使用真实支付类型和原生 SVG，原彩、比例、间距与版权／本地化协调。桌面与手机分别看图，验证空／单个／多类型及换行，不把开关 true 或本地无支付数据当作已经看到了图标；若后台未完成支付配置，明确这一实际前提，不能伪加截图中全部品牌。
- 视觉评审与功能验收分别完成：按 [design-and-content.md](design-and-content.md) 实际看首屏、商品、分类、服务与 Footer 在桌面/手机和空店/有商品状态的表现。精品对照用户认可的成熟基准，检查字级、比例、密度、留白、卡片、详情及手机细节；变得空旷或粗糙时回退并打磨，不为差异推翻可靠结构。基础与自主模式对照本批与历史记录检查实质构成差异。各模式修正粗糙细节，不把某一项目的固定布局写成自主任务通用断言，不以自动相似度或通过项数量替代审美判断。

### 所选交互与动效

执行 [retail-interactions.md](retail-interactions.md) 中与本次选用效果对应的检查。实际触发 hover、焦点、触控与展开状态，覆盖单图/多图和辅图加载失败、快速购买、减少动态效果及模块重载。检查操作不遮住真实商品信息、不造成布局跳动或全目录辅图抢加载。鼠标效果必须有完整手机与键盘路径；静态截图、仅检查 CSS 选择器存在都不能称交互验证通过。

各模式比较本批和近期作品的陈列与交互。精品允许保留成熟卡片、导航与购买反馈，按本次商品小幅适配并复测；基础与自主模式不能仅重复 hover CSS、图片放大和全区渐入便声称独立设计。均不为差异硬加特效或不适用品类的动画，记录实际观察与修改，不设自动“高级感”分数。

评审静态细节截图时等待图片解码和相关 CSS 过渡完成，避免把淡入中间态误判为双影或过低对比度；动效快进快退另行实际操作。截图存在不等于已看过，要直接查看所报告的关键桌面/手机画面。新增字串放入 locales，开关关闭、无增强 JS 与 reduced-motion 的路径仍可使用。

参考 [EstateKid 整站观察](estatekid-layout-study.md)、[Cozyster 整站对照](cozyster-layout-study.md) 等零售站完善流程时，分别记录参考已读结构、当前创建器已有能力和本次实际实现、验收的组件。不能把参考站按钮、加载骨架、示例推荐、未使用 CSS 或空博客当成真实功能；不能把创建规范更新称为脚本已实现整套展示层或旧成品全部重制。

选用吸底购买时，验证变体切换后的双价、库存、数量、真实加入和错误反馈；选用底部导航时，验证真实路径、购物车数量、320px、安全区、键盘及浮层互不遮挡。完整快速查看核对当前商品／规格与失败回退；推荐／最近浏览覆盖真实多商品、空结果、无访问历史和不可售状态。联系侧栏与数值指南核对本店事实。未选用的模块不强行加入，也不套用参考站售后规则。

### 导入后首页或 Footer 缺失

先区分编辑器中整个分组缺失，还是存在分组而前台隐藏。分组缺失时查看导入后实际文件，沿 layout → group JSON → section Liquid / schema 查依赖；平台可能跳过校验失败的文件，不要仅反复改 CSS 或在首页硬编码一个替代页脚。

首页 404 时先核对导入后的 templates/index.json 和其中依赖的 section 是否实际存在。已复现过：品类全局替换把 icon 默认值改成不在 options 中的文案，并把 block ID 改成带空格的文字，导致 section 与首页模板均未成功导入。修正 schema 后恢复依赖 section，再恢复 index.json；不能把 404 模板替换成首页来掩盖缺失，也不能将此问题归因于没有导入商品 CSV。

还须读取导入后的 `config/settings_schema.json` 实际内容，不能只看文件名存在。已观察到导入后该文件变成 `[]`，同时 FAQ 与 index 缺失、编辑器报配色方案错误；本地包则同时有普通 Brand 分类误挂元信息、FAQ 显式空默认值及裸 richtext 保存值。逐项修正对应数据并原生保存，保留原 settings_data／配色定义；不能把每次 404 都归因于这组问题或重置店主配置。导入后关键文件、编辑器提示和真实保存返回分别留证。

在当前授权的草稿或本地修复副本中重现；有后台编辑条件时，重新保存缺失 section 以取得真实 `FileSaveError`，再据错误修复并恢复 group。已出现过的错误为 `Invalid schema: setting link_list type can only be inserted once in the settings.`，对应将同一 settings 数组中的额外菜单移到独立菜单 blocks。遇到其他错误依据实际返回处理，不预设都是同一个原因。

后台修复必须同步回本地源码后再打包，比较 ZIP 中对应文件与已验证源码一致。分别记录“本地模拟通过”“Shopify 原生保存通过”“实际草稿预览通过”和“最终 ZIP 新导入通过”；在旧草稿保存相同修复文件不等于新 ZIP 已单独重新导入。只在本次授权的店铺和主题操作，不复用示例项目的店铺、主题 ID 或浏览器窗口编号。

新 ZIP 导入须等平台处理完成，再核对实际草稿 ID、根路径 HTTP 状态与首页内容，不能把成功上传或创建草稿当作导入成功。读回 index、依赖 section、schema 与 settings_data；平台添加合法文件头或重排 JSON 时比较解析后的值，不把格式化误判成丢失配置。批量修复对全部成品执行静态与归档核验，实店抽样范围如实报告；没有逐店验证时不声称所有已导入店铺都已修好。已上传的旧副本须重新导入修订包或单独修复，替换本地 ZIP 不会自动更新后台。

## 首页截图交付

建站与主题视觉改版默认每站额外交付一张实际桌面首页截图，基础、精品及自主模式均适用；批量站逐站截图，不用同一母版预览替代其他站。仅处理 CSV、未交付主题的任务不因此扩成建站任务；用户本次另定截图范围时从其要求。

- 截图来自本次最终主题的真实浏览器渲染，包含本站图片、配色、文案与对应商品状态，优先完整长图以看清导航、主视觉、分类、商品陈列和 Footer。没有导入商品时如实展示空店状态；使用本地商品模拟时说明其数据与真实导入的区别。不能用参考站截图、旧主题图、拼出的网页模型或生成图冒充本次成品。
- 在字体、图片及相关过渡完成后保存并直接查看截图，检查照片完整、文字清楚、无异常空白／重叠／缺图。长图须滚动检查下方懒加载媒体，不能仅凭文件存在或图片请求成功称截图完整。截图只展示已捕获状态，不替代手机、交互或整站验收。
- 全页截图漏绘或受长度限制时，可用当前允许的浏览器截图工具逐段实拍后拼成长图；依据实际滚动位置核对重叠与连续性，保留原帧和坐标于工作目录，不补画缺失内容，不带入重复页头、漏段或错误接缝。工具不可用时继续其他已授权工作，并明确截图仍待完成，不能编造预览或绕过浏览器限制。
- 默认保存真实 PNG；工具返回 JPEG 时可沿用真实格式与扩展名，或将已解码像素无损重封为 PNG，不仅改扩展名。核对解码、尺寸和落盘文件。文件名区分站点且与本站日期一致，例如 `品牌-01-home-YYYY-MM-DD.png`；既有命名有约定时沿用。
- 通过验收后，将这一张截图与对应 ZIP、CSV 放进同一站点交付文件夹，保持独立文件，不装入主题 ZIP；手机截图、原帧、素材、来源与审计记录默认仍留工作目录。交付清单关联截图与本次主题版本；本次视觉修改后刷新受影响站点截图，避免交付旧画面。全站归集仍只复制 CSV。
- 最终提供每站截图的可点击绝对路径，并说明来自本地预览或实店；适合时内嵌一张供直观查看。截图不需要上传 Shopify，也不证明主题 ZIP 已经实店导入。

## ZIP

### 抓取商品/分类时的交付边界

默认提供三个独立成品：可直接上传的主题 ZIP、可直接导入的商品 CSV 与按上述规则验收的实际首页截图。截图只供预览。不要把主题、CSV、截图、全部商品图片及报告再套成一个整合 ZIP；复用旧项目打包脚本时取消其默认素材归档步骤。只有用户明确要求离线素材备份时，才把归档包作为额外交付，并说明它不用于主题上传。

把成品放在同一个“品牌或参考站简称(品类)”交付文件夹内，例如 output/shopify/psychobunny(服装)；用户另指定名称时从其要求。默认一个 ZIP、一个 CSV 和一张首页截图；明确要求五份目录时为一个 ZIP 加 csv1.csv…csv5.csv，仍每站一张截图，同站同品类、选品不同。修改已有站时保留原命名和份数，不把五份误删成一份。源码、素材和报告在工作目录，核对成品文件清单、大小和校验值；历史成品不混入、不覆盖无关文件。

主题 ZIP 仅保留实际运行所需资源，商品 CSV 和首页截图均不放进主题 ZIP；CSV 图片使用已核对的可访问 URL。分类映射应已在主题与 CSV 中配合实现，不依赖另导入 JSON、截图或图片包。核对 CSV 的商品/变体/图片/分类与采集结果一致，最终分别给主题 ZIP 和 CSV 的链接与大小，以及首页截图链接。抓取中产生的图片副本、清单与报告留在本地工作目录，不成为店主安装步骤。

本次启用 [全站归集](all-store-csv-collection.md) 时，另在本批交付根目录建立日期归集子目录，额外复制各站已验收 CSV。该目录只提供集中取用，不替代各站原 CSV、不装入主题 ZIP，也不算新增站点。交付后逐文件回读哈希、数量与源文件对应关系；后续改价或换品须同步本次范围内的归集副本。最终同时给出归集目录位置。

根目录直接包含 assets、blocks、config、layout、locales、sections、snippets、templates，无外包文件夹。旧主题不用 blocks 时保留空目录条目，不为凑结构重写主题。原主题确有用途且 Shopify 当前支持的附加结构如 listings 可保留。

不打包 Git、node_modules、凭据、备份、报告、独立政策草稿附件或技能文件。可编辑内置政策正文必须保留在主题 Liquid/schema/presets/保存配置中。可用 `shopify theme package --path THEME_DIR` 或辅助脚本，再核对 ZIP 实际条目、CRC 和空目录。

独立页面工作流还须包含当前 `assets/service-pages-manifest.json`、实际 Page 模板／section 与阅读样式；最后修改品类、正文、地址或标题后刷新清单并核对来源 Footer JSON／正文哈希，不能交付旧品类清单。它属于主题内的运行／安装内容，不是额外独立安装文件；上传 ZIP 本身仍不会创建后台 Pages。

比较 ZIP 内每个运行文件与已验证源码的字节一致性，解压到临时目录再次执行基础审计，防止交付旧包。最终 CSV 与已往返核对版本也应字节一致；记录 ZIP、CSV、截图实际大小和 SHA-256，并核对截图对应最终主题。工作目录报告不可引用旧项目、错误输出路径或未运行的检查。打包后没有新改动就不无理由重复全套测试；有修改则重验受影响部分并重新打包核对。

使用时核实最新上传限制。已查到官方移动端要求小于 50 MB；脚本保守采用 50,000,000 bytes 为严格上限，达到即拒绝，成品留余量。当前限制更低时调整 max-bytes，不当作永久规则。

官方参考：[上传大小说明](https://help.shopify.com/en/manual/shopify-admin/shopify-app/mobile-online-store)、[Theme Check](https://shopify.dev/docs/api/shopify-cli/theme/theme-check)、[Theme package](https://shopify.dev/docs/api/shopify-cli/theme/theme-package)、[颜色设置](https://shopify.dev/docs/storefronts/themes/architecture/settings/input-settings#color_scheme_group)。

## 补充组件检查

- 字体加载后检查 Footer 的两列服务标题和长导航，覆盖 990px 等桌面临界宽度。菜单组标题不沿用巨大的展示标题字号；文本分类入口不保留原图片卡片的固定空白高度。
- 商品换图使用真实第二张图；待第二张解码成功才隐藏主图，失败保留主图。触屏的详情入口可见且易点，按钮和独立图片链接不能嵌套在另一个链接内；新增媒体外层后复测编辑陈列的轨道宽度和重排。
- 核对场景、Banner、分类及编辑陈列图来自实际互联网照片，保留来源与许可记录；无品牌站逐张看图筛查明显品牌、文字、水印和可识别品牌款。未经用户另行明确要求，不使用生成图，也不以抹标绕过筛查。
- 打包全部引用到的默认场景和响应式变体，包括当前未启用、店主可重新添加的原生图文 section。不能只换首页现用图片，让旧品类照片或文字在新增模块时重新出现。
- 定制组件继承可编辑颜色方案及动效设置。检查系统字体回退、店主动效关闭、减少动态效果和移动端图片设置，不能提供看起来可编辑但不影响实际页面的设置。

## 最终答复

整站设计的本地验证使用 [storefront-depth.md](storefront-depth.md) 的页面职责，不能只验证首页或以空 `filters` 夹具代替真实筛选。集合/搜索的 GET 参数、规格不可售、图库媒体回退、空/有商品购物车与内容页都应有本次运行证据。辅助脚本与共用 CSS 提供行为基线，不证明不同网站已有独立视觉；仍须查看桌面/手机图并对照实际近期作品。

给出品牌交付文件夹位置，以及文件夹内主题 ZIP 和 CSV 的可点击绝对路径与大小，同时给出每站实际首页截图的可点击路径，适合时内嵌一张预览。用两步说明“上传主题 ZIP → 在产品中导入 CSV”，简述商品与分类将如何自动出现，说明截图仅供查看及其本地／实店来源。默认不再附整合包、图片备份包或报告下载链接，除非用户明确需要。

抓取任务同时给出实际商品、可售规格和顾客分类数，简要说明币种与可售快照不持续同步；标签分类入口不等于独立后台集合。未知库存数量不能通过“有库存”措辞伪装成已核实数量。

简述品类和视觉方向、重要改动、静态 / 官方 / 真实预览分别验证了什么、未验项、条款已保存或仍为草稿及待补事实。主题与 CSV 完成主题及目录展示，首页截图供查看；店铺自身的收款、配送、域名及待填政策仍取决于真实后台配置，不能承诺本地成品自动完成全部开店设置。没有实际观察的检查不得称通过，本地交付明确没有发布。
