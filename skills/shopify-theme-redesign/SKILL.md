# Shopify 原生主题设计与装修

用中文沟通，面向美国市场，默认自然美式英语店面文案。收到品类和装修命令后，先完成下述三技能准备，再直接实施、制图、验证并交付 ZIP；不只提供计划。先确定本次为基础复刻、精品复刻或自主设计，不能把三种模式混成同一个展示母版。

指定编号时，读取[编号精品共用说明](references/numbered-premium-styles.md)和对应一份风格参考。精品3—7是整站设计标准，覆盖首页、分类、商品卡、商品详情、Footer及手机；不是给旧精品换色。约85%的成熟关系保留应针对**所选编号参考**，不重新套回 Cozyster 或精品2。这五套已做参考站视觉研究，尚无配套原生主题母版；参考截图不等于可上传 ZIP 或新店已验收。未指定编号时保留现有默认路线。

本次明确的新视觉参考优先于模式默认站；明确要求自主设计时不因附了商品来源网址而强行复刻。精品站优先沿用用户认可的历史精品成品，未指定具体成品时以 Cozyster 为成熟基准：**默认约 85% 保留成熟布局与组件关系，约 15% 做品类和局部视觉适配**，这是设计取向而非像素相似度分数。导航、首页节奏、卡片、分类工具条、详情购买区与 Footer 的比例、字级、留白及交互精细度优先保持，不为跨站差异大幅重构。基础站与自主设计仍按各自规则实施；基础不是低保真、功能简化或 `native-base.zip` 的外观。各模式覆盖整站完成度；视觉参考不自动成为抓取商品或移植经营资料的授权。

跨站设计采用[图片去重与站间差异规范](references/site-diversity.md)：**轮播每一帧、Hero、场景／分类／专题图及商品卡片、详情／变体图片均不得跨站复用，同一原图改名、裁切、调色或压缩仍算重复。** 同站响应式派生和真实商品的卡片／详情复用允许，支付标识等功能图标不计入照片去重。精品站按上述成熟基准优先、小比例调整执行，允许复用经过验证的布局和组件，通过独立素材、协调配色、内容及少量陈列变化形成特点；不因结构相近强制推翻精致版式。基础站、自主设计仍规划实质构成差异。未逐项高还原时不声称一比一复刻。真实商品、本站身份／经营规则、原生功能、可编辑性及后台授权边界继续保留。技能更新不自动回改历史 ZIP，局部修改和历史翻新仍服从本次范围。

精品严格复刻的 Footer 可见栏目、名称、数量、顺序、布局和默认开关以本次参考截图及最新指示为准，优先于旧底稿的 14 项可见清单和 Newsletter 默认关闭。包内完整政策职责不等于全部摆在 Footer；未展示的必要正文保留可编辑草稿／归档。本次 Cozyster 图2的四列、十个菜单链接及开启的订阅见 [Footer 严格复刻规则](references/footer-and-policies.md#精品严格复刻的可见-footer)。其他精品参考按其实际 Footer，不固定套用本次十项；基础与自主模式的原规则不变。

## 编写前先完成三技能准备

执行 [design-skill-prerequisites.md](references/design-skill-prerequisites.md)。**本技能是唯一调用入口**：Taste Skill、独立 Design Skill 与 Garden Skills 前端模块的完整规则和资源已内置在 `assets/design-skills/`，无需用户逐个调用或另装外部技能。安装/分享本技能时保留完整目录；开始建站前运行 `python -X utf8 scripts/check_design_skills.py`，核对内置三项入口、资源及来源快照完整性，再读取它们和本次适用参考。内置缺项先修复或安装齐全并重验，已有完整集成直接复用。

**检查成功并读取适用规则之前，不先创建或修改主题代码或生成页面设计成品。** 不把外置 Anthropic `frontend-design` 作为已集成独立 `design` 的替代证明，也不只凭本机曾安装过三个独立目录就跳过内置检查。准备完成后按已授权范围自主执行，不逐项重问是否开始。来源、资源修复及三者与 Shopify 约束的衔接以该参考为准；这些设计技能和记录不进入 Shopify 主题 ZIP。

## 开始与交付范围

- 先读 [reference-and-build.md](references/reference-and-build.md)。有用户原主题就在副本装修并保护现有配置；无原主题则自主编写原生 Online Store 2.0 主题，不索要原主题、不套用 Dawn / Horizon 等官方主题。
- 无原主题可用 scripts/prepare_theme.py 提取 assets/native-base.zip。它只复用原生功能，**其首页组成、DOM、section 顺序、照片和 CSS 都不是默认设计答案**。允许重写展示组件、增减 sections 和改变构图，保护数据、表单与 Footer 引用。
- 本次明确品类优先；不把参考站商品或上次品类沿用为当前定位。必要时问范围，同时推进不依赖答案的工作。没有品牌资料用 shop.name，经营事实缺项按已授权方式标记 #待填入。
- **每个新站绑定当次唯一一份店主资料。** 姓名、主体、目标店铺及获准使用的联系资料不得从上一站、历史示例或其他目录自动补齐；同一站继续修改时只使用该站已确认资料。当前资料未给出或归属不清时，仅询问缺项并继续独立工作，不能拿旧姓名占位，也不能编造一份“唯一身份”。可跨站复用的是已确认的经营规则和功能实现，不是个人资料。
- 默认交付根位置为当前工作区的 output/shopify，用户另指定则从其要求。交付文件夹默认名为“品牌或参考站简称(品类)”，例如 psychobunny(服装)、joola(运动产品)；混合目录按实际范围标注，用户明确指定文件夹名时保持原名。抓取商品默认放主题 ZIP、一份商品 CSV 和一张本站实际首页截图；用户要求多目录时可为一个 ZIP 加 csv1.csv 至 csv5.csv 等指定份数，仍每站一张截图，各 CSV 保持本站相同品类、不同选品。修改已有成品时保留原文件名、CSV 份数和站点范围。源码、素材、中间数据、脚本和报告另存工作目录。同品牌再次生成时，已确认属于本流程的旧成品另存工作/历史目录，不覆盖或删除无关文件。
- 用户要求抓取官网商品/分类时，执行 [source-catalog.md](references/source-catalog.md)：核对完整公开目录与实际集合成员，逐规格筛选可售状态，排除内部物料，确认源币种、图片和分类覆盖。全站范围优先于早先举例的单一品类，不因首页导航或前几页只有部分商品就宣布完成。
- **批量站的商品按实际款族互斥分配**，执行 [跨站商品与图片唯一性](references/catalog-uniqueness.md)。同款的颜色、尺码、不同来源别名只能归一个站，不靠改标题、handle、SKU 或拆变体冒充新品。先核实足量独立可售款再分站；数量不足继续扩源，不能静默复用、降数或声称完成。对本批全量及可访问历史登记查重并说明覆盖范围；本次明确指定相同官方目录等另有范围时从其要求，不自行扩大历史翻新范围。
- 用户授权自主选小商品时，执行 [curated-smallwares.md](references/curated-smallwares.md)：可从 TikTok Shop、品牌/商家公开目录等核实商品，按每站定位分别编排商品和分类，商品按上述款族规则不跨站共享。**当前不要求中国国内货源**；不把“可以从 TK 取”变成只准一个平台。保留真实可售规格、价格、图片与出处，最终 CSV 按 Shopify 当前支持格式验证，并同步主题的分类、指南和商品相关展示。
- 用户要求无品牌通用品时，排除知名品牌款、标识、联名和可识别角色/IP 图案；不能将品牌商品删去名称后冒充通用品。记录来源与实际筛选依据，不把无标识判断宣传成已完成商标、专利或图片许可审查。
- **带商品的交付还须执行 [商品类别与库存完整性](references/catalog-completeness.md)。** 每件商品分别填写有效 Shopify 标准类别 `Product category`、自定义 `Type` 与主 `Collection`／真实分类关联；不能只做 Type 和前台导航。新建本地目录默认按店主已授权规则，为每个真实可售规格独立随机分配 **60–99 件虚拟配额**，启用 Shopify 跟踪；分配一次并按稳定规格身份保存，重跑不重抽，无需再次询问 99／1,000 件。当前明确指定的其他数量、实际库存同步或不跟踪例外优先；不自动回改旧 CSV 或实店库存。配额不是来源／实仓库存证明。单／多地点按平台实际支持处理，交付前运行 `scripts/catalog_audit.py` 并核对分配映射或实际库存依据；缺必验数据不称完整目录。
- 执行 [pricing-and-promotions.md](references/pricing-and-promotions.md)：新建站默认仅从 **10%、15%、20%、25% OFF 四档**为每站随机选择一次并保存；同站重跑沿用已选比例，公告措辞可变化。在工作目录保存逐站折扣计划；售价 = 有依据原价 ×（1 − 折扣率）。构建时确定，顾客访问时不随机变化；本次明确另定比例或不促销时从其要求。逐变体保留有效划线原价，不对旧折后价重复打折。**顶部已启用优惠条、CSV 双价及所有商品展示须使用本站同一比例，改价／换品不能清掉其中一项。** 来源只是批发价或价格区间不合适时，补查零售参考或按授权重新选品，不编原价。交付前向 `promotion_audit.py` 明确传入本站 `--multiplier` 并实际看图；只修改本次新建或明确指定的旧站，不自动回改历史成品。
- 用户要求“所有模板／全部 CSV”时，重新盘点指定位置的全部实际成品，包括品牌、未编号目录、嵌套文件夹中的成品副本和多份 CSV；不沿用上次仅编号站或仅根目录的范围。区分成品与工作、来源、历史备份／整合资料包，保留逐路径清单。价格验收逐规格按本站折扣计划核对 `Price`、更高的有效 `Compare-at price` 及公告，不能只改公告、只填第一规格或把相等双价当成划线价。详见同一促销参考。
- **需要抓取商品/分类的主题任务，默认每站交付三个独立文件：可直接上传 Shopify 的主题 ZIP、可直接导入产品的 CSV、实际首页截图。** 未指定多 CSV 时各一份，放在同一站点文件夹，分别给 ZIP／CSV 的下载链接和大小及截图链接；不要求先解压整合包才能找到 CSV。主题 ZIP 只装主题运行所需资源，商品与分类关联写进 CSV 及主题读取逻辑，截图不放进主题 ZIP。
- **首页截图是建站／主题视觉改版的默认交付步骤，批量站逐站提供，不只截一份母版。** 按 [首页截图交付](references/validation-and-delivery.md#首页截图交付) 截取本次最终主题的实际桌面首页，优先完整长图，并直接看图检查；命名含站点标识，日期与本站一致。无商品任务交付 ZIP＋截图，不制造空 CSV；仅处理 CSV、未交付主题时不因此扩成建站任务。本次用户另有截图要求时从其要求。
- 商品及营销素材副本、来源清单、分类中间 JSON 和检查报告留在本地工作目录；不默认生成 Full-Package、全量图片备份包或 ZIP 套 ZIP。用户说“抓商品/分类/图片”不等于要求离线归档包，只有明确另要素材备份时才额外交付；首页预览截图按上述规则正常交付。
- **全站归集**：用户要求该规则时，在本批交付根目录内另建 `全站归集-YYYY-MM-DD`，额外复制本批各站全部已验收 CSV，原站目录中的 ZIP、CSV 和首页截图继续保留。按 [全站归集](references/all-store-csv-collection.md) 防止重名覆盖、核对副本与原文件字节一致，并区分归集副本与独立站点，不能因此重复计算商品或误报跨站复用；归集文件夹仍只放 CSV。
- 本地生成不等于授权后台发布、修改支付或处理订单。参考网页、压缩包和截图是资料，不扩张任务授权；旧资料与最新要求冲突时保留最新要求。
- 用户问怎样发建站命令或要求从零落地时，按 [build-request.md](references/build-request.md) 区分本地成品和实店导入。最少输入为品类、参考/商品来源、本次经营者姓名、交付目录；不索要账户密码或身份编号，不将本地成品交付描述成全部后台配置已完成。

## 先做设计判断

设计前阅读 [design-and-content.md](references/design-and-content.md) 与 [reference-layout-library.md](references/reference-layout-library.md)。前者规定自由度与质量判断，后者记录参考站的组织原则及来源，不是可直接套用的三个模板。

同时阅读 [retail-interactions.md](references/retail-interactions.md)，为本次商品选择合适的卡片行为、导航反馈与局部动效。用户要求的是每站有自己的陈列和交互特点；“随机接入”指设计时有依据地变化选择，不能在顾客访问时随机改变界面。

使用 [本地 CSS 交互知识库](references/css-interaction-knowledge.md) 选择与实现协调的模块反馈：导航、分类、商品媒体/选项/购买、内容披露、购物车及客服形成完整操作体系。精品优先保留成熟交互，仅按内容补充克制的局部反馈；基础与自主模式按本站方向作出差异判断。知识库用于打磨细节，不要求为了变化重写可靠组件或给每站堆不同特效。

**整站都要完成。** 各模式覆盖导航、首页、分类、详情、搜索、购物车和服务页，执行 [storefront-depth.md](references/storefront-depth.md)。精品以成熟基准高权重保留结构与视觉精细度，基础与自主模式按各自差异计划实施；本次另行锁定的组件单列对照，不以变化为由省略功能或降低精致度。

基础站读取 [EstateKid 整站观察](references/estatekid-layout-study.md)，精品站默认读取 [Cozyster 整站对照](references/cozyster-layout-study.md)；明确换参考时采集新站。两个站的首页结构、卡片系统、PDP 和手机行为分别处理，不混成固定组件全集。自主任务可按需借鉴购物层次；不把源码按钮、示例推荐、未使用样式或空博客当成功能证据，不把新增规范说成旧 ZIP 已自动具备。

执行 [frontend-design-system.md](references/frontend-design-system.md)，把标题文案、字体搭配、字重/字宽、行长与断行当作每站设计的一部分。标题应针对实际选品、自然且有辨识度；导航、价格、商品名及政策保持清楚。上述三项必需设计技能检查和读取完成后，按本店采用适用指导；Anthropic frontend-design、ui-ux-pro-max、web-design-guidelines 是额外参考，不替代三项前置准备。不机械叠加全部样式或引入与 Shopify 无关的框架/动画库；不因协作技能的原型审批步骤打断已获授权的自主设计。可分享技能不依赖别人的绝对路径，安装与读取按当前运行环境重新核对。

执行 [配色与色面构成](references/color-and-surface.md)：精品沿用成熟基准的明暗层次与可读性，配色可局部变化，不强制改成深色、强色或重排色面；其余模式可自由采用深色、饱和纯色、明暗交替及局部浅色。各模式让色面、商品陈列与内页形成系统，比较整页效果后决定，精致度优先于变化幅度。

**配色须先保证文字清楚，再追求气质。** 前景／背景、按钮底／按钮字成对设计，主色与中性色协调，少量强调色承担重点，不随机拼色。按上述参考对实际渲染色面、透明叠加、图片文字、正文／价格／辅助字及 hover／焦点／选中状态做对比度和看图验收；普通文字至少 4.5:1，大字及必要控件视觉部分按适用要求至少 3:1。消除浅底白字、深底黑字及全区低透明度；成熟精品约 85% 保留／15% 适配的方向不变。

- **精品首页优先保留成熟基准的顺序、构图与购物密度**，只按真实品类调整个别专题或陈列；基础与自主模式按本站购物任务编排。真实内容不足时做明确适配，不填无关模块或扩大空白。
- 自主模式不默认左文右图、eyebrow + 双行大标题 + 描述 + 按钮、三图标横条、图文各半生活区、双列 FAQ 或深蓝页脚。精品可沿用成熟基准中适合本站的构成；各模式都不能把功能骨架直接当精致成品交付。
- 各模式先查看本批全部站点计划、可访问历史素材记录及近期实际截图。`inspect_design_history.py` 只辅助发现直接子目录中的少量记录，不能替代嵌套／ZIP 成品和全部历史主图查重；按 site-diversity 执行本批全量图片比对及桌面／手机对照，没有历史证据时写明覆盖范围。
- 在本次工作目录写简短设计记录与本批素材计划，说明模式、技能准备、商品与受众、参考与观察范围、首屏／导航／分类／陈列／字级／色面／内页／交互、手机及回退；列出相对最相近成品的实质变化、锁定组件与必要适配。图片保留来源标识、许可依据、成品文件与响应式素材族，全部记录留工作目录，不写入共享技能或最终成品文件夹，不要求用户先选方案。
- 精品的跨站变化以独立图片、配色、文案及少量专题／陈列适配为主，允许保留导航、卡片、详情与购物区的成熟结构。基础与自主模式继续要求主要构成、购物节奏及内页的实质差异。各模式精致度与整站完成度不因批量而降低，保护购买路径和性能。
- 默认将适合的精品零售交互实际做进成品，例如真实第二张商品图切换、快捷操作显现、分类图像联动或细节展开；不要求每站加入同一套效果。对照近期成品同时审视布局与交互，不把一份统一 hover CSS 当作每站的特色。正规、可靠、高级来自一致的排版、图像、信息和完整操作状态。
- 保留精致、现代、清楚、有商品质感的目标，配色允许更自由。白/浅灰、绿/蓝/珊瑚红及早期对紫/米黄/棕的大面积使用限制属于旧方向，不作为通用色表或禁色清单；以本次明确要求与真实品牌约束为准。不强迫所有站深色，仍避免复杂渐变，卡片圆角最多 8px。精品配色优先服从成熟结构与图片，其他模式结合构成、字体、陈列与交互作独立判断。

## 不能因视觉变化丢掉的功能

- 商品、真实价格与可售状态、变体、快速购买、购物车、搜索、账户、多语言、国家/货币与结账入口均须使用 Shopify 原生对象、routes、money filters、表单及 Cart API。不能用静态卡片或本地数组替代真实购买；不干扰支付、订单和结账系统。
- 保留 layout/theme.liquid、content_for_header、content_for_layout、app 接入及所需系统模板；首页使用 templates/index.json。有原主题时保留其功能、设置 ID/类型/值与兼容性，不整体重置配置；自主构建时提供匹配的配置、颜色方案定义/实例/role/CSS。
- 内容模块可在 Theme Editor 修改、排序、隐藏、删除、重新添加；新 sections 有有效 schema/presets。Header / Footer 使用原生可编辑结构，现有顶部菜单链接不擅改。
- **头部必须有顾客可用的分类购物入口。** 首页分类自动展示还不够：Header 同步读取实际非空集合，再回退真实 Type / 已确认分类映射；桌面形成清楚的横向主导航，手机有紧凑分类捷径和完整菜单入口。保留现有菜单及嵌套目的地，去重补充分类，不要求先在后台建菜单；空店的计划分类为明确不可点击预览，导入后被真实链接替换，不生成会 404 的集合链接。前台动态导航不等于创建后台 Menus。详细数据与边界见 csv-and-home-catalog。
- 执行 [csv-and-home-catalog.md](references/csv-and-home-catalog.md)：空店前台默认 8 个中性商品位、4 个分类位；商品区默认 All products，分类自动读取非空集合，再回退 Type，无分类时用真实全部商品入口。实际可见商品出现后自动替换，不补假卡。占位数量是数据配置，不规定卡片造型或首页位置。
- 主商品网格默认桌面 4 列、手机 2 列，保留标题、价格、正确选项和快速购买；可以另加编辑陈列或专题入口。不能为新设计把首页商品和分类区藏掉、拉到冗长叙事之后或改成依赖手选的死数据。
- 至少两张不同、匹配品类的互联网真实场景照片随包放入 assets；所有轮播帧和关键营销图执行跨站来源与图像查重，不能残留上一站或基线的激活图、默认回退图和重加模块预设图。构图服从本次版式，不固定右侧商品留白或 8:3。Banner、生活场景、分类和编辑陈列图默认从互联网寻找真实照片，**不自行生成图片**；只有用户之后另行明确要求生成时才采用图像生成。无品牌站逐张查看并筛除明显品牌标识、可识别品牌款、文字和水印，不通过抹标把品牌商品伪装成通用品。优先使用有明确商用许可的图库或本次获准使用的来源照片，记录来源及许可；找不到合适素材时继续换来源，不悄悄改用生成图。用户明确要求抓取官网图片时按本次范围使用真实场景/模特照片及商品媒体，不移植店主身份或虚构官方关系。可编辑文案写在 HTML/Liquid 中；WebP 压缩并验证手机裁切、srcset/sizes、首屏优先与下方懒加载。
- 服务信息和可编辑 FAQ 要易找；布局可变，事实不变。Reviews 默认关闭；Newsletter 一般默认关闭，精品严格复刻按本次参考截图／明确指示的开关执行，不把旧关闭值带回成品。不伪造评价、销量、倒计时、认证、优惠或履约承诺。
- 图片须保持真实比例并按主体选框：商品轮廓完整，场景／人像的 cover 裁切逐张逐断点看成品，不把窄竖图塞进宽横框、不统一靠上裁脸。HTML 尺寸与 srcset 描述匹配实际文件，保留可编辑焦点及必要手机图；按 [图片适配规则](references/design-and-content.md#图片由版式决定) 核对原图和实际画框，拉伸与严重裁坏都须修复。
- 不加载多余第三方 JS，不用 Three.js、GSAP 等大型动画库；轻量 CSS 尊重 prefers-reduced-motion，手机触控和速度优先。

## Footer、条款与可靠交付

先读 [merchant-policy-defaults.md](references/merchant-policy-defaults.md) 及其政策资产：用户已确认的 30 天收货退货、免费退运、无补货费、未履约商品 15 分钟取消，以及采用的美国配送、退款与客服规则，是后续本地模板的默认依据；不要再次把已确认条件写成 #待填入。新参考站不覆盖这份经营底稿；本次最新指示和已确认目标店规则优先。

默认个人经营，姓名从本次资料读取；资料中的账户邮箱不自动作客服邮箱，用户明确确认本次公开客服邮箱时只用于本站。Footer 公开联系地址按本次证件或按证件整理的地址资料填写，缺失部分标记 #待填入，不从历史店铺补齐。使用实际原生站内联系表单，不制造空邮箱栏。通过 prepare_theme.py 的 --operator-name 和 --operator-address 传入当前姓名与地址；Footer、内置 Contact Information / Legal Notice 共用可编辑地址设置，不将真实个人资料写进可分享的技能默认值。

执行 [footer-and-policies.md](references/footer-and-policies.md)：About Us、联系、品类指南、物流、追踪、售后、退换、付款、隐私和适用条款正文直接含在 ZIP 中，保留可编辑草稿及适用阅读界面；精品严格复刻只把本次参考规定的入口摆进可见 Footer，其余必要正文可隐藏归档。应用资产中的完整正文；有姓名后默认仅对实际隐私配置和必要法律披露保留集中核对项。用户指定的隐私参考采用其结构及通用内容改写，替换身份，不将未知数据处理实践当事实。已有真实后台政策经核对后可优先展示，不能声称 ZIP 自动创建 Policies / Pages 或与后台双向同步。Footer 按当前模式及参考实施，保留正文与编辑能力。

**Footer 文档默认使用独立页面跳转，不再用政策弹窗。** 解析实际已发布 Page／非空原生 Policy URL，保留正文及 Page 模板；缺后台页面时保留明确待配置状态，不能猜造会 404 的链接或用查询参数假装独立页面。按实际目的地去重菜单、政策、联系与指南入口，隐藏去重后的空栏目。Footer 默认提供可关闭的 Shopify 原生语言、国家／对应货币控件，只显示后台真实选项；单选项显示当前值，不能伪造多语言或汇率转换。具体实现和后台边界以该参考为准。

**所有后续模式的 Footer 默认加入并开启支付图标区**，参考 Cozyster 底部的原彩标识横排、版权行与手机换行，不能只保留一个没有验收的开关。用真实 `shop.enabled_payment_types` 和原生 SVG；不照抄参考站的支付开通状态，不为凑九个图标展示未接受的方式。创建、重加模块与保存配置都默认开启，交付前按 [支付图标区](references/footer-and-policies.md#底部支付图标区所有模式默认开启) 核对空／单个／多个真实选项与桌面／手机；尚未配置付款导致无数据时明确说明后台前提，不修改或代替支付配置。

完成后执行 [validation-and-delivery.md](references/validation-and-delivery.md)，同时完成视觉评审与功能检查：

- 实际看每站桌面／手机首屏、全部轮播帧、商品／分类区、详情及 Footer，并查看本批并排截图。执行 `scripts/audit_site_diversity.py` 检查营销图及设计，另以 `scripts/audit_catalog_uniqueness.py` 核对本批商品款族及全部店面照片；两个报告缺一不能声称跨站无重复。精确重图／同款须按原规则处理，不能替换不匹配图来规避。精品对照成熟基准检查保留程度与精细度，允许已记录授权的结构复用；基础与自主模式继续检查实质构成差异。相似度与检查数量不能代替实际看图和操作。
- 同时检查分类的真实筛选/排序、商品的实际规格和图库、搜索的初始/结果/空结果、购物车空/有商品、联系/内容页。商品数量必须带说明，可按设计隐藏；不能将 `products_count` 误判为 ID 后删掉原生数据逻辑。不能用 `filters: []` 的本地预览证明筛选样式和功能已完成。
- 每个 section/block 的 settings 数组最多一个 link_list，额外菜单用独立 blocks；inline_richtext 默认值不能含 <br>；保守采用不超过 25 字符的 section/block/preset 名称。沿 layout → group JSON → section → blocks 核对 Footer，不靠首页硬编码补丁掩盖缺分组。
- 运行基础 scripts/theme_audit.py、可用官方 Theme Check 和实际可用预览，修复本轮问题。测试核对真实行为与响应式布局，不把旧主题的 section 顺序、双行标题、固定 Hero 比例等设计选择写成通用断言。
- 对选用交互实际执行鼠标、键盘与触控检查；换图覆盖真实多图、单图和加载失败回退，检查减少动态效果、快捷购买及 Theme Editor 重载。静态截图不能证明动效可用，未选择的效果不必为凑测试而实现。
- 将头部分分类作为单独验收项：空/默认/已有分类菜单、集合/仅 Type/无分类/空店、长店名、多分类、手机捷径及菜单、本地化路由、去重与当前项。不能只验首页分类卡片就宣称头部已完成；微交互同时核对可用性和各站实际差异。
- 抓取任务核对源数据 → 可售筛选 → CSV → 主题分类的数量与关联，实际渲染完整分类映射，避免 Liquid 循环上限截断。若选用尺码/规格预览，链接读取导入后真实 variant 对象，验证目标商品选中了对应规格，并检查展开后的手机布局。
- 打包前必须通过 theme_audit.py 的结构 ID、select/radio、空 schema 默认值、richtext 保存值及主题元信息归属校验，覆盖 defaults、presets、保存配置及已禁用模块。保留 Brand／logo 与原配色设置，不假设 settings_schema 首项为 theme_info。修改品类文案时不要对整个 JSON/Liquid 做全局替换，保护 section/block ID、图标枚举、设置 ID 与文件引用；Theme Check 无报错不替代此检查。新包导入须等处理完成并读回实际关键文件、确认草稿 ID 与首页，不能把上传成功或旧草稿保存当作新 ZIP 验证。
- 退货、物流、售后、条款、FAQ、公告和商品提示采用同一已确认政策；检查 15 分钟取消没有混入旧参考站的 1 小时，免费退货没有混入客户付费或补货费。Final sale 必须有实际指定名单，不能由来源站标签或折扣推断。
- ZIP 根直接为 assets、blocks、config、layout、locales、sections、snippets、templates；检查 CRC、源码一致性和当期上传限制。报告与开发工具放 ZIP 外。
- 最终给出主题 ZIP 的绝对路径与大小；抓取商品时同时给出独立 CSV 的绝对路径与大小，并说明“先上传主题，再导入 CSV”。同时给出每站实际首页截图的可点击路径，适合时内嵌一张预览，说明本地模拟或实店截图来源；截图仅供预览。简述本次设计区别、分类自动关联方式、实际验证范围及待填资料，不将备份/报告列为必需安装文件。明确本地模拟、原生保存、实际导入分别验证到哪一步；不能把截图、旧基线证据或本地 200 称为新 ZIP 已通过实店验证。

只在用户要求改技能时更新技能；收到装修命令时持续完成主题交付，不停在研究或反复索要原主题。
